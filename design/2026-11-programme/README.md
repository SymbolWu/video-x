# video—x · 放映目录 / The Programme

2026.11 · 三端视觉重设计提案

> 把私人片库做成一本可以翻开的放映目录：观看时是一间暗房，整理时是一张日光下的编目桌，手机上是一册随手可翻的放映单。

这是一份**可点的静态设计原型**，不是已经落地的版本。它不依赖数据库、不启动 API，也不会写入真实媒体盘；所有页面由 HTML / CSS / JavaScript 构成，影片封面和公开资料来自仓库里已有的设计样例。

## 快速打开

在仓库根目录运行：

    python3 -m http.server 8099 --bind 127.0.0.1 --directory design/2026-11-programme

然后访问：

- 设计总览：http://127.0.0.1:8099/
- 观看端：http://127.0.0.1:8099/web.html
- 管理端：http://127.0.0.1:8099/admin.html
- 移动端：http://127.0.0.1:8099/mobile.html

加上 **?capture=1** 会隐藏演示框架并冻结动画，用于截图；移动端用 **?screen=discover|library|detail|filters|player&capture=1** 指定初始画面。

## 为什么再设计一版

现有实现已经能完成真实链路：扫描、草稿核对、手动发布、Web / Android 播放与跨端续播。问题不在功能，而在视觉系统还没有替这些功能建立秩序。从代码与运行截图看，主要有四件事：

1. **强调色太多，且没有语义。** 观看端 token 同时存在 **--accent: #ff6f91**、**--blue: #748be4**；Android 主题里又有 **Pink**、**Lavender**、**Gold**。颜色更像装饰，而不是“喜欢 / 状态 / 可操作”的语言。
2. **容器比内容更响。** 卡片圆角、胶囊筛选、均匀网格、渐变遮罩反复出现，海报与剧照被装进同一种盒子里。画面没有机会形成节奏，页面看起来“整齐但平”。
3. **观看端和管理端共享同一种深色情绪。** 管理端 **AdminShell** 使用 **#141517** 与 **--studio-rose**，和观看端的深色粉紫非常接近。两个完全不同的工作状态——沉浸看片 vs. 做判断——没有在视觉上分开。
4. **层级靠字号，缺少排印。** 标题、正文、标签、状态大多落在同一套无衬线字重里；日期、编号、文件事实没有属于自己的“档案字体”。信息很多，但读起来没有先后。

这一版先做减法：把颜色收成一个强调色，把卡片边界拆掉，把标题交给宋体，把日期、编号、字段交给等宽字；再用“暗房 / 日光纸”两种光线区分观看与整理。

## 2026.11.26 第二版调整

第一版评审指出：管理端页头过高、统计区不一致；观看端与移动端元素过大、一屏作品太少；移动端分类难触达、系列与收藏夹浪费空间；整体气质偏“服装展览”。本版据此做了以下调整：

- **管理端页头压到 100px 内。** `admin-page-head` 从 46px 宋体展示标题改为 30px 无衬线工具标题，说明压成一行；录入与资料库共用同一条 `metric-strip`，数字、标签、辅助信息同一套尺度。录入队列首屏从 4 行增加到 7 行。
- **观看端去掉展示型尺度。** 首页 Banner 从 92vh / 760px 降到约 48vh / 432px；片库从 5 列改为 7 列，一屏可看到两排以上影片；页标题从 64px 收到 32px，区块标题改为无衬线 26px。移除“第 47 期”、SHELF 编号和大段宣言，保留影片信息与继续观看。
- **移动端按手持场景重排。** 分类从 10px 文字斜杠改为 44px 高的横向按钮；影片从 2 列改为 3 列；系列与收藏夹改为 2 列卡片网格；“收藏”页在收藏夹下补上“我喜欢的”影片网格，不再留下半屏空白。
- **减少展览感。** 宋体保留给片名和详情主标题；页标题、区块标题、卡片标题改为无衬线。管理端统计与表格使用工具型字号，不再用展示型排印承担操作界面。

## 视觉系统

完整数值见 [tokens.json](tokens.json) 与 [styles/tokens.css](styles/tokens.css)。

### 两个光线

| | 观看端 · Nocturne | 管理端 · Daylight |
| --- | --- | --- |
| 底色 | #0B0A09 | #F4EFE6 |
| 文字 | #F2ECE1 | #1C1814 |
| 强调 | 黄铜 #C7A25C | 牛血红 #8E3A2F |
| 状态 | 细线、进度、黄铜点 | 鼠尾草绿 / 琥珀 / 牛血红 |
| 字体 | 宋体标题 + 等宽标签 | 宋体标题 + 无衬线正文 + 等宽字段 |
| 形状 | 0 圆角，靠边线与留白组织 | 0 圆角表格、1px 线、纸面层次 |
| 动效 | 700–1000ms 画面进入；1.03 倍缓推 | 180ms 悬停；抽屉 480ms |

### 排印

- 中文标题：Songti SC / STSong / Noto Serif SC，字间距 0.03–0.06em。
- 拉丁副题：Bodoni 72 / Didot，斜体、0.1em 字距。
- 正文：PingFang SC 12–14px，行高 1.9–2.1。
- 标签 / 日期 / 编号：SF Mono / Menlo 6.5–10px，0.08–0.16em 字距。
- 管理端字段标签用等宽大写；观看端片名用宋体，二者不混用。

### 形状与间距

- 观看端、管理端的主体容器 **0 圆角**；只有头像、播放圆钮、移动端底部抽屉保留圆形/20px 圆角。
- 间距以 4 为步进，常用 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96。
- 观看端桌面 7 列海报；移动端 3 列影片、2 列系列与收藏夹；管理端 248px 侧栏 + 40px 内容边距。
- 触控目标：移动端 44–48dp；观看端主要按钮 50–56px。

### 组件语言

| 组件 | 规则 |
| --- | --- |
| 海报 | 2:3 原图、无圆角、无白边；悬停只上浮 7px 并显示一条“查看影片”细线。 |
| 剧照 | 16:9 全幅；文字压在底部渐变，不额外加卡片。 |
| 状态 | 4px 圆点 + 文字，颜色只作辅助。 |
| 输入 | 管理端下划线输入；观看端没有输入。 |
| 表格 | 表头等宽 7.5px；行高 68–76px；悬停仅改变纸面一层。 |
| 抽屉 | 观看端右侧 430px；移动端底部 88%；两者都可 Esc / 点遮罩关闭。 |
| 播放器 | 无侧栏、无列表；标题、时间轴、版本、返回四项。 |

## 从代码到界面

设计没有增加新的业务实体。字段仍然来自现有契约：

- 影片：Media / MediaDetail 的 title、summary、releaseYear、categoryName、durationMs、posterId、backdropId、stillIds、actors、directors、franchises、editions、resumeMs。
- 个人状态：isFavorite、rating、watchedAt、resumeMs 仍彼此独立；原型里分别演示，不互相覆盖。
- 录入：ImportQueue 的状态、完整度、文件路径、来源候选、分集容器；原型用 9 条样例覆盖待核对、已确认、已发布、阻断与分集线索。
- 系统：卷容量、Worker 心跳、数据库、ffprobe、媒体根标识与访问状态，对应 SystemStatus 的只读事实。

原型中的喜欢、评分、续播、草稿、卷容量为**界面演示值**，不写数据库。影片封面、横图、影人肖像来自现有 **design/2026-11-redesign/assets/cinema**；本目录的 **assets/cinema-sources.json** 与 **assets/asset-sources.json** 保留了公开资料页与图片地址。

## 已覆盖的交互

- 观看端：顶部导航、搜索浮层（⌘K）、分类筛选、排序循环、右侧筛选抽屉、海报进入详情、详情喜欢/评分/已看、播放器打开与返回、收藏夹入口、空结果、图片缺省回退。
- 管理端：侧栏切换、录入队列表、状态筛选、搜索、选中行更新核对抽屉、保存/确认提示、资料库搜索、列表行进入编辑、编辑分区提示、系统状态。
- 移动端：底部四项切换、分类、实体切换、排序、筛选抽屉（草稿 / 预览数量 / 重置 / 应用）、详情喜欢/已看/评分、播放、搜索、简单收藏与我的页。
- 所有浮层：Esc 关闭；筛选项有选中态；状态有文字不只靠颜色；支持 prefers-reduced-motion。

## 已知边界

- 不包含真实视频解码、上传、来源抓取、发布事务、Android 原生返回栈或权限。
- 管理端的演员、系列、收藏夹、分类、标签、片商、任务、归档页只保留信息架构占位，未逐屏绘制；它们沿用同一种列表 / 抽屉语法。
- 移动端用 HTML 模拟 390×844；正式实现应使用 Compose 原生布局，不能把页面装进 WebView 交付。
- 截图使用 Chrome headless 生成；系统字体与浏览器字体会带来细微差异，正式验收以运行中的页面为准。
- 图片只有 780px 宽的横图；大屏首屏会有轻微放大，正式接入应从素材服务取更高分辨率。

## 建议落地顺序

1. **Token 先行。** 把 tokens.json / tokens.css 的颜色、字体、间距、圆角迁入 **packages/design-tokens**；先不改变业务组件。
2. **共享控件。** 统一按钮、下划线字段、状态点、表格表头、抽屉。管理端优先，因为它的状态最多。
3. **观看端外壳。** 先替换 WatchHeader、experience.css 与片库工具栏；详情与播放器随后替换。播放器内部逻辑不动。
4. **管理端外壳。** 替换 AdminShell 与 admin-shell.css，再逐页迁移录入、片库、编辑器。表格列与操作逻辑保持现状。
5. **Android 主题。** 先在 CinemaTheme.kt 收掉 Pink / Lavender / Gold 多强调色，替换为单一黄铜 + 宋体标题；再改片库、详情、筛选。
6. **逐页验收。** 用 1440×900 与 390×844 两个视口，按 **docs/standards/interface.md** 检查默认 / 空 / 失败 / 返回位置 / 焦点。

## 验证记录

- 静态页面无构建步骤，直接由 python3 -m http.server 提供。
- 浏览器检查：1440×900（观看端、管理端、总览），390×844（移动端全部画面）。
- 已检查：图片加载、筛选计数、收藏/评分状态、详情进入与返回、播放器打开、移动端抽屉滚动、键盘 Esc 关闭浮层。
- 未做：真实 API、数据库、Android 构建、播放解码。以上需在正式实现阶段按 docs/implementation/status.md 的入口重新验收。
