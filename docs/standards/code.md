# 代码规范

## 代码放在哪里

| 位置 | 职责 | 在 video-x 中的例子 |
| --- | --- | --- |
| `apps/admin/src/app`、`apps/web/src/app` | 挂载后的路由、外壳、导航与页面编排 | 管理端所有路由复用同一个 AdminShell。两个应用的 `src/main.tsx` 只负责启动和顶层 Provider。 |
| 各 Web 应用的 `src/features/<业务>` | 页面、领域组件、查询、状态转换和本功能的样式放在一起 | 追加版本归影片编辑，目标目录树归存储，播放会话归播放。 |
| 各 Web 应用的 `src/shared` | 该应用多个功能共用、与具体页面无关的组件和展示逻辑 | 图标、图片和格式化。业务页面的提交与发布规则归对应功能。 |
| `packages/ui`、`packages/design-tokens` | 双 Web 共用的选择框、弹窗、反馈、基础视觉值 | 修复下拉框和按钮时，先检查公共实现能否覆盖同类入口。 |
| Android 的 `ui/<业务>`、`ui/components`、`core` | Compose 界面、共享控件、网络与持久化。ViewModel 管理界面状态和用户事件 | 播放器和详情独立，返回后仍能定位影片。 |
| `apps/server/src/modules`、`platform`、`entrypoints` | 业务用例、数据库/队列适配、进程装配 | API 与 Worker 复用同一套整理及发布约束。 |
| `packages/contracts`、`packages/sdk-*` | 契约来源、客户端生成物与适配器 | 修改请求或响应，同时更新校验、生成结果和消费者。 |

功能初次实现时就放进对应目录。一段代码承担列表渲染、网络轮询和批量提交等多个独立职责时，沿状态和副作用的归属拆开。只有一个调用点且能清楚表达业务的函数可以留在原模块。新增跨功能依赖时选择明确的导出入口，检查循环依赖；通用层保持对上层业务无感知。正式客户端通过工作区包的公开入口复用代码，原型中的效果在正式组件和样式中实现。

## 实现与数据

- TypeScript 保持严格类型。网络输入、外部来源和文件元数据在边界校验，异常使用可识别的错误。组件用业务名，React 组件用 PascalCase，hook 用 `use` 前缀。Kotlin Composable 用 PascalCase，事件函数和普通函数用 camelCase。JS/TS/CSS 采用仓库锁定的 Prettier，Kotlin 缩进四格。生成的 SDK 由契约工具维护。
- 查询键包含实际影响结果的实体、过滤、排序和分页。表单草稿与已保存记录分开。保存时提交用户打开表单时的 revision；冲突保留输入并提供重新读取的路径。服务端区分字段省略、显式清空与空关联集合。
- 服务端拥有发布、文件所有权、访问权限和数据一致性规则。资料与关联在同一事务变更。需异步执行的文件动作记录任务状态与可恢复位置，重复执行能够判定结果；同名目标必须阻断并保全两个文件。新增迁移须同时考虑已有数据和回退后的读取兼容。
- 样片、账号与测试数据库使用独立配置。日志记录任务标识、阶段和可操作的错误。验收截图或 PR 使用合成内容，清除账号凭据与私人媒体信息。
- 每个缺陷优先在最接近故障的层次补回归。浏览器验证焦点、滚动、选项和返回；集成测试验证数据库、队列、文件和实际解码；原生端再验证系统返回和设备播放。已有用例足以覆盖时直接复用。

## 自动检查的范围

`pnpm format:check` 检查应用手写 TS、TSX、CSS、服务端测试、共享包手写源码及工程脚本。单文件整理可用 `pnpm exec prettier --write <文件>`。`pnpm check:boundaries` 检查双 Web 源码的位置，以及 JS/TS 构建时的静态依赖、CSS 导入与资源引用。它能识别正式前端引用原型目录或另一个应用实现等情况。类型约束由 `pnpm typecheck` 验证。业务内聚、跨端语义和用户体验仍需按实际场景评审。

共享 UI 的公开入口 `packages/ui/src/index.ts` 只显式转出组件与类型。弹窗、选择框、分页等独立交互各自拥有实现模块。边界检查会阻止在入口中再定义组件。
