## 录入工作台 · 手动草稿与在线资料

工作台支持在无媒体盘时保存手动草稿，之后通过相对路径绑定文件并实际探测。JavDB 已作为首个来源插件接入，支持单条与所选草稿抓取、候选选择和按字段采用。录入队列分别显示来源返回情况和草稿缺项。来源结果保存在草稿上，人工核对当前版本并点击发布后才写入片库。剧照保留来源链接，封面可保存为本地图片并采用。


## 2026-11-19 · M2 本地录入与真实播放

M0、M1 已验收。M2 已打通单文件作品从扫描到两端续播的主流程。完整编辑、更多媒体组合和异常恢复仍在本阶段的验收清单中。

| 环节 | 当前实际行为 |
| --- | --- |
| 扫描 | API 将扫描任务持久化到 PostgreSQL。worker 从带 UUID 标识的只读根读取 MP4/MKV，通过 FFprobe 保存实际字节数、时长、容器和音视频轨道。重扫按路径复用记录，按字节数及纳秒修改时间识别更改。只有完整扫描才标记缺失文件。 |
| 录入 | 列表展示片名、分类、演员、系列和实际媒体信息，可按片名、演员或文件搜索，可筛出资料缺项、阻断、待确认和已发布项目。编辑支持片名、主分类、年份、简介、备注、中文标记、演员、系列。草稿修改或发现文件更换后需要重新确认。 |
| 发布 | 人工确认绑定草稿版本。「手动发布」单独执行，在数据库事务中建立作品、默认版本、文件段及演员和系列关系。发布时复核文件和挂载标识。 |
| 播放 | 观看 Web 通过浏览器原生播放器起播。Android 使用 Media3，提供全屏播放器。媒体地址绑定登录设备与播放会话，支持 GET、HEAD、单区间、后缀区间和 416 越界响应。 |
| 续播 | 两端以实际起播、暂停、拖动和自然结束事件保存毫秒位置，播放期间每 10 秒记录一次。打开详情或创建会话不会清空进度。新设备接管后，旧会话失去写入权。 |

### 验收结果

- Chrome 实际播放 125 秒的 H.264/AAC MP4，在 31.250 秒暂停。Android 模拟器点击「继续播放」后，从服务端收到的真实起播事件位置为 31.250 秒。
- Android 退出时记录 36.395 秒。回到 Chrome，起播事件为 36.395 秒，浏览器读取的播放位置为 36.396 秒。两端均已解码出视频帧。样片画面内的测试图案每 22 秒循环，浏览器进度条和记录使用整段媒体的时间。
- 19 项服务端及数据库测试全部通过，覆盖重复扫描、损坏文件、并发发布、文件替换、Range/HEAD、回退、旧设备补发、接近片尾时暂停及自然结束。Web 构建、TypeScript 检查、双 SDK 再生成、Android debug APK 与 4 项 Android 单元测试通过。
- Docker 已从项目构建 API 和网关镜像。独立 Compose 片库中完成迁移、只读媒体挂载、worker 探测、测试资料的确认与发布，以及双向播放验收。开发片库中另有一条 22 秒样片，特意保留为待核对，方便试用人工发布流程。

## Download 录入与移动发布 · 2026-11-20

录入工作台可逐层打开 Download，跨子目录勾选文件、绑定空草稿、为多条草稿设置目标或预设一个新子目录，再人工核对、手动移动并发布。队列可查看目标和任务状态。目录计划保存即撤销旧核对，发布成功时更新正式文件路径。管理端各页面的侧栏共用原型对应的线性图标。

实测使用独立 PostgreSQL 库、合成 MP4 和临时挂载的 HFS+ 测试卷。同卷样片移动后保留 inode。设置目标后出现同名文件时，提交前和执行中均可阻断。播放会话从新位置返回完整字节及 HTTP 206 分段，FFmpeg 可解码。跨文件系统复制到第 1 MiB 后向复制进程发送 SIGKILL，正式记录仍不可见，源文件完整。重新领取任务后从既有偏移续写，校验、发布和清理完成，重复投递复用同一条作品记录。
