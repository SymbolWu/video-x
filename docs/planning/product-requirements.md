# video-x 产品需求文档

评审稿 1.1 · 2026-11-17 · 基于现有 Web、后端及 Android 代码重新梳理

video-x 是个人自用的影视资料库与播放器。它应完整承接现有系统中有用的整理、检索和观看能力，让用户更容易录入、修正、找到和播放自己的内容。界面可以更简洁，操作能力必须有明确去向。

本稿是产品评审基线。文中“应”“支持”描述目标行为；HTML 为交互模拟，数据库为候选设计，均不代表正式功能已经实现。已明确的用户决定继续生效；本次新增的产品选择集中在第 14 节，尚未视作用户确认。

录入交互已按旧结果列表和容器操作重审，详见[录入列表核对与分集容器](ingest-interaction-v07.md)。

建议先读第 2 节的旧版问题、第 4～6 节的录入和编辑规则，再看第 9 节筛选排序。完整能力承接清单见[现有系统能力基线](legacy-capability-baseline.md)。

## 1 定位与首版边界

用户在同一个资料库里有两种工作状态：看片时希望内容直观、播放可靠；整理时希望资料可控、修改充分、批量操作高效。观看端使用深色影院主题，管理端提供足够的信息密度，两者共用资料和个人状态。

| 项目 | 已确定的规则 |
| --- | --- |
| 使用范围 | 个人自用，一个账号与默认个人资料；Web 观看、Web 管理、Android |
| 网络与部署 | 当前 Mac，登录后自动恢复；外网主要服务资料抓取；首版不建设多人公网服务 |
| 入库控制 | 后台可扫描、探测、匹配；正式入库必须人工确认、手动发布 |
| 分类 | 每部作品、每位演员只能属于一个分类；系列沿用单主分类；父分类可筛选后代 |
| 人物名称 | 保留常用名 full_name 与详细名称 detailed_name；不设 alias |
| 个人状态 | 喜欢、1～5 星评分、手动已看、收藏夹、实际播放进度分别维护 |
| 作品结构 | 旧上下部、Part1/Part2 按有序分集；同一集的物理文件段另行管理 |
| 播放 | MP4、MKV 为首批识别和验收范围；能否直接播放取决于真实编码及客户端 |
| 数据迁移 | 保留有用资料、关系及个人状态；旧任务与旧进度不迁；大小重新读取；旧喜欢时间可未知 |
| 明确后置 | 待清理标记、人物生日/简介/角色名、网站评分、独立 genre、外挂字幕管理、转码、多账号公网 |

下载箱录入包含选文件、规划整理目录、核对和手动移动发布。在正式资料目录可以原位建库。实现边界、恢复规则和旧版依据见[文件整理设计](storage-intake.md)。

## 2 现版本的能力与具体问题

2026-11-17 查看了本地运行的影视录入入口，仍为“导入、整理、发布”三步；当前浏览器没有可编辑草稿，因此下述编辑与保存行为以仓库源码为依据，没有向旧系统添加文件、抓取或发布测试资料。

| 现有能力或问题 | 代码事实 | 改版要求 |
| --- | --- | --- |
| 录入并非只有标题和年份 | 完整编辑抽屉已有名称、发行日期、番号、封面、布局、简介、中文标记、分类、标签、演员、系列、分集及文件信息 | 新编辑器至少承接这些业务能力，不能用少量核对项替代完整编辑 |
| 抓取关系不容易修正 | 演员、系列标签的快捷移除要求已有数据库 ID；抓取的临时资料可能不满足 | 临时与正式关系均能移除、替换、重新匹配 |
| 来源结果可能盖住人工整理 | 草稿重试结果通过对象合并覆盖同名字段，缺少逐字段接受流程 | 抓取结果进入候选区；人工修改留在当前草稿，先比较再采用 |
| 文件事实和用户输入混在一起 | 大小、格式、分辨率、时长、文件路径均为普通输入；另有“替换文件”控件未传入处理回调 | 探测事实只读；提供重新探测、选择文件、改绑，而非修改显示字符串 |
| 清空和局部保存语义不完整 | 更新前过滤空值；系列更新使用 if(series)；部分缺省状态被写回默认值 | 明确“不修改”“清空”“替换”；改简介不能重置喜欢或中文标记 |
| 草稿只存在当前浏览器 | localforage 保存草稿列表与任务 ID | 服务端保存草稿；换浏览器、后台重启后能继续整理 |
| 录入强绑定 JavDB | 页面将爬取、Cookie 与导入流程直接绑定 | 先选择内容和工作目标；来源可选，手动整理也能完成录入 |
| 新原型存在能力倒退 | V0.5 草稿主编辑仅标题/年份，关系在另一弹窗；不能完整维护资料 | 本稿要求统一完整编辑器，并用同一组用例验收草稿与已发布维护 |
| 筛选有遗漏 | 旧 Web 有评分上限/包含未评分、播放次数上限、入库天数；Android 有 576p/480p 与双向排序 | 逐项恢复检索意图，不能随“清理”分组一起删除这些条件 |

详细证据见第 15 节。对于只有 API 支持而旧界面未暴露的日期、体积和时长范围，清单单独标注，避免把“代码有字段”描述成“用户原本就能操作”。

## 3 导航与三端分工

| 场所 | 页面与入口 | 完整任务 |
| --- | --- | --- |
| Web 观看端 | 发现、片库、收藏；个人入口含历史、设置、进入管理 | 找片、按演员/系列探索、播放、评分、喜欢、整理收藏夹 |
| Android | 发现、片库、收藏、我的；详情正常返回栈 | 同义筛选排序、播放与续播、个人整理、服务器地址与连接测试 |
| Web 管理端 | 入库；作品、演员、系列、分类、标签、片商；来源差异、任务、系统 | 完整资料编辑、关系维护、文件版本、来源提案、批量操作与运行诊断 |

片库中切换“影片、演员、系列”，分类是浏览范围。收藏包含喜欢的影片、喜欢的演员、自建收藏夹。演员、系列从作品详情也可进入，不要求用户先进入管理模块。

移动片库首屏只保留必要的页面标题、视图切换、分类、搜索、排序与筛选入口；不放宣传语和大段说明。更多筛选收进面板，已选条件仍可见、可单项取消。管理端完整表单不塞进手机观看页。

## 4 内容从进入到长期维护

### 4.1 支持的进入方式

| 用户情形 | 入口 | 结果 |
| --- | --- | --- |
| 有一批本地视频 | 选择服务器媒体目录或已扫描文件，可多选 | 创建导入批次和草稿，读取真实文件信息 |
| 抓取失败或没有合适来源 | 草稿中“手动填写” | 不依赖来源也能完成资料与文件核对 |
| 已知编号或页面地址 | 草稿中“搜索来源”，填写关键词、编号或 URL | 显示候选与来源身份，人工选择后采用指定字段 |
| 同一作品新增一个版本 | 作品编辑器“添加版本”或导入时“关联已有作品” | 保留作品身份、收藏、评分；新增版本与文件关系 |
| 文件可能缺失、损坏或质量过低 | 版本详情中重新检测、直接从已选媒体盘的下载目录选取候选文件 | 核对和试播后用确认的文件名入库到原文件所在目录，原文件与进度保留。新版本继承原默认标记 |
| 多个文件属于上下部 | 批次多选“组成分集” | 生成作品组，每集有自己的资料、版本和进度 |
| 一个版本被切成多个文件 | 编辑器“文件段” | 在同一版本下安排文件段顺序，避免误建多部作品 |
| 想先整理资料再找文件 | 新建手动草稿 | 可保存不完整资料；能否无文件发布按第 14 节建议执行 |

“本地文件”指服务器能读取的媒体文件；浏览器本地图片上传与媒体盘文件选择分别呈现。用户不需要输入 FFmpeg 安装位置。

### 4.2 状态与按钮含义

| 操作或状态 | 保存在哪里 | 是否影响观看端 |
| --- | --- | --- |
| 保存草稿 | 服务端导入草稿，允许不完整 | 否 |
| 接受某项来源值 | 当前编辑内容；需保存草稿或保存变更 | 否，不自动发布 |
| 资料就绪 | 校验通过，仍未人工确认 | 否 |
| 确认当前草稿 | 绑定本次草稿版本、候选和文件绑定 | 否；随后仍需手动发布 |
| 发布选中项 | 正式作品、关系和版本；幂等执行 | 是，成功后可查看作品 |
| 修改已发布资料并保存 | 对当前正式资料应用明确变更 | 是；不要求重新导入 |
| 获取已发布资料的新来源结果 | 差异提案 | 否；接受并保存后才生效 |
| 归档与恢复 | 保留正式资料与关系，修改可见状态 | 归档后不进入正常片库，恢复后重新出现 |

保存草稿不会隐式确认。确认后修改资料、来源身份、关系或文件绑定，必须取消原确认并重新核对。重试、任务完成、重启都不能产生新的发布决定；只可恢复同一次已经授权的发布。

批量发布只处理本次明确选中且已确认的集合。单项失败保留该草稿及失败原因，其余成功项能查看结果；重试不会重复创建作品。分集组按一个结构单元校验与提交，避免只发布父项或漏掉所选分集。

### 4.3 结果列表是主要核对区

获取资料后，列表直接显示封面、标题/编号、演员/导演、分类/系列、发行日期、中文标记和文件；简介、标签、完整文件信息可以行内展开。分别展示“获取结果、当前资料缺项、人工确认”，不以抓取成功代表资料齐全，也不要求逐条打开编辑器。

列表允许筛选缺项或失败条目，显示具体缺失内容；缺演员、封面等非必填项只是提示，发布阻断单独标明。勾选在人工确认之前就可使用，用于分组和批量操作。所选条目可以在一个汇总面板中人工核对并确认，随后手动发布；未选内容不受影响，存在未确认项时不得静默跳过后发布其余项。

完整的列表字段、选择范围和分集操作见[录入交互规则](ingest-interaction-v07.md)。

## 5 完整资料编辑器

### 5.1 页面组织

录入先在结果列表核对，仅需要补充或修正时进入完整编辑器。草稿和已发布作品使用同一套编辑分区。顶部显示标题、草稿/已发布状态、保存状态；主区使用“基本资料、图片、演职员、归类与关联、分集、版本与文件、来源”切换。右侧在需要时展开来源对照或发布检查，不让普通资料编辑依赖反复打开小弹窗。

草稿页保留上一条、下一条与批次返回；存在未保存内容时，提供保存后离开、放弃、继续编辑。失败保留输入并定位字段。已发布作品保存前显示本次变更摘要，涉及共享人物、移除版本、调整分集归属时另外说明影响范围。

### 5.2 字段与可操作范围

“两阶段可改”指草稿与已发布资料都能修改。数据库技术字段不作为表单必填项。

| 分区 | 用户可维护的内容 | 编辑规则与界面用途 | 数据依据 |
| --- | --- | --- | --- |
| 基本资料 | 标题、简介、备注 | 两阶段可改；备注不被来源刷新覆盖；片库、详情显示标题和简介 | media_items.title/summary/notes；沿用 display_name/movie_desc/remark |
| 编号 | 主编号、编号类型、补充来源编号 | 两阶段可改和清空；来源 ID 与本地作品 ID 分开；搜索可用 | media_identifiers.scheme/value/is_primary；旧 serial_number 转换 |
| 日期 | 未知、仅年份、完整日期 | 不要求伪造月日；完整日期校验；用于展示、筛选和排序 | release_year/release_date/release_precision |
| 中文资料标记 | 支持、不支持、未知 | 允许人工判断；与当前文件是否有中文字幕轨道分别展示 | supports_chinese；沿用旧中文标记 |
| 图片 | 封面、横竖布局、背景图、剧照及顺序 | 选已有素材、图片 URL 获取、本地图片上传、移除；失败可重试且保留旧图 | assets、media_images、cover_layout；旧封面与扩展图片信息 |
| 演职员 | 添加/移除/替换人物、演员或导演职责、显示顺序 | 新旧人物都能移除；就地新建缺失人物；人物姓名使用独立共享资料维护 | credits、people；旧 movie_actor 与 extra_info 导演 |
| 分类与标签 | 一个主分类、多个标签 | 两阶段可改；未分类是有效值；标签支持搜索、创建和移除 | primary_category_id、media_tags、tags |
| 系列与片商 | 系列成员关系、系列内位置、片商及职责 | 多关联能力有模型依据；首选复用已有项；移除关系不删除资料主体 | franchise_items、media_organizations；旧 series、extra_info |
| 分集 | 独立作品/作品组/集、所属组、集号、集标题 | 可调整归属与顺序；不能用物理段号冒充集号；有子集时禁止直接改成可播放单片 | kind、parent_id、episode_number |
| 版本 | 名称、备注、默认版本 | 可添加和归档；默认版本影响列表文件事实；作品个人评分不随版本改变 | editions.name/notes/is_default/archived_at |
| 文件绑定 | 选择/改绑文件、段顺序、重新探测 | 通过文件选择器操作；更换文件先预览时长和内容差异；不执行隐式移动 | edition_parts、media_files、storage_roots |
| 来源 | 候选选择、来源链接、采用/拒绝字段、字段锁定 | 原始快照只读；手工资料不被重抓自动覆盖；解除锁定也不会自动接受 | source_records、metadata_snapshots、各实体 field_state |

只读区域显示真实路径、文件名、字节数、容器、编码、分辨率、时长、音频/字幕轨道、最近探测与在线状态。探测失败显示未知和原因；用户可换绑正确文件或重新探测，不手填“4K”“2 GB”制造文件事实。

个人评分、喜欢、手动已看、收藏夹和续播属于个人使用，不作为发布必填项。观看详情提供就近操作；后台编辑资料不能覆盖这些状态。

### 5.3 新建与编辑共享资料

添加演员先搜索常用名、详细名称及来源身份，显示分类和已有作品数，避免误选同名人物。没有合适结果可就地创建：常用名必填，详细名称、性别、头像可空，分类使用明确选择或“未分类”。不要求用户手填内部编码。

草稿中的新人物、系列保留为待创建资料，发布时一并落库。复用已有演员时，“从这部作品移除”只移除关系；“编辑演员资料”明确修改共享人物，显示影响的作品数并独立保存。修改影片分类不顺便修改演员分类。

系列、标签和片商选择器同样支持复用与就地新建。页面显示“新建资料”和“关联已有资料”的区别，不能仅靠名称自动合并。已有资料的来源绑定、合并和归档使用明确操作。

### 5.4 清空 修改与冲突

用户删除简介、取消系列关联、移除演员、取消评分，都应有可保存的结果。未触碰字段保持原值；清空可空字段写空值；提交空关系集合代表移除这些关系。不能过滤空值后让界面显示已清空、数据库却仍保留。

同一资料在两个页面编辑时，后保存的一方遇到版本冲突，应看到“服务器当前值、我的修改”并重新选择。批次重试和来源刷新同样遵守此规则，不能按最后请求无条件覆盖。

### 5.5 发布检查

| 类型 | 项目 |
| --- | --- |
| 必须解决 | 标题为空；结构/编号冲突未裁决；集无有效父项或同父集号冲突；版本段号重复；文件绑定无效；尚未确认当前草稿 |
| 普通文件发布要求 | 至少一个有效版本及可核对文件；根目录当前可用；探测成功或明确处理探测失败；具体放行策略见第 14 节 |
| 不应阻断 | 缺演员、缺系列、无来源匹配、缺简介、缺封面、发行日期未知、归入未分类 |
| 提示后选择 | 疑似同一作品、已存在其他版本、中文标记与轨道不同、资料不全 |

发布检查不能强迫用户为了消除警告填写不存在的数据。组本身没有文件是正常状态，其实际可播放分集单独校验。

## 6 录入与修正的连续场景

### 6.1 一部影片正常入库

选择文件 → 探测与可选抓取 → 结果列表查看实际值和缺项 → 按需行内修正或完整编辑 → 汇总人工确认 → 手动发布 → 在观看端查看。用户可在抓取前先手填资料；抓取回来后逐项比较，而不覆盖已经输入的标题或演员。

### 6.2 抓错作品或抓错演员

来源区域展示当前选中页面和匹配依据，允许重新搜索或粘贴 URL。换候选先展示差异，已人工输入和锁定的字段默认保留。演员和系列关联同样参与对比，既能移除错误候选，也能换为已有资料。重新核对完成前不允许沿用旧确认状态发布。

### 6.3 上下部与物理文件段

在结果列表勾选上部/下部视频，直接点击“建立分集组（创建容器）”。同一面板填写容器名称、选择资料复制自哪一集，预览并调整集顺序；确认后在原列表展开容器和各集，一起核对发布。容器不绑定视频，不复制原编号或来源身份；各集原资料与文件保留。可调整集顺序或解除分组，修改后重新确认。

如果是同一版本的多个物理文件段，则从“版本与文件”安排段顺序，不创建分集容器。文件名中的 CD1、Part1 仅作为提示，不自动决定。

### 6.4 已入库作品新增版本或修复路径

从作品详情进入版本维护，选择“新增版本”或“修复现有文件绑定”。新增版本保留作品资料与个人状态，默认版本由用户决定。修复同一文件的路径保留可验证的断点；换成不同内容不能沿用旧文件段的毫秒位置，需要提示重新开始或明确迁移选择。

### 6.5 批量整理

批次列表在待核对阶段即可多选，支持批量分类、标签增删、重试失败项、组成分集、批量确认和发布。组成分集入口紧随当前选择，不另开一页重新勾选。批量确认先展开将确认的标题、来源、分类和文件摘要，逐项标出阻断项；不能用“全部任务完成”代替核对。

已发布作品支持批量分类、标签增删、加入收藏夹及归档。批量标签操作明确区分追加、移除、替换；默认追加。选择器显示已选数量与跨页选择范围，批量操作不悄悄作用于未选记录。

## 7 资料维护与组织

| 对象 | 浏览与使用 | 维护操作及边界 |
| --- | --- | --- |
| 演员 | 头像、双名称、喜欢、片库作品；作品筛选排序 | 新增、双名称/性别/分类/头像编辑、参演关联、来源补全、合并、归档恢复 |
| 演员资料补全 | 从演员维护筛选缺头像/详细名称的资料，查看成功/失败/跳过 | 承接旧后台任务；新版结果先形成提案，由人接受；不限死旧分类字符串 |
| 系列 | 系列概览、有序作品、开始/继续观看 | 名称、说明、分类、封面、成员增删和完整顺序；不冒充组/剧/季 |
| 收藏夹 | 观看模式展示作品，整理模式多选 | 创建、改名、说明/封面、添加/移出、顺序；保留旧“移动到另一个收藏夹”意图 |
| 分类 | 片库范围选择，含后代；隐藏只收起入口 | 层级、名称、顺序、显示开关；隐藏含影片的分支先提示；删除需指定迁移去向 |
| 标签 | 详情及筛选使用；一部作品可有多个标签 | 名称、分类、属性组、可见性、关联维护；隐藏保留既有关联 |
| 片商 | 作品资料中的制作/发行/品牌及筛选 | 名称、说明与作品关系；内部身份不等于来源编码 |

收藏夹“复制”仅向目标添加；“移动”先确保目标包含成员，再从当前收藏夹移除，同一次提交完成。目标已有该片时不重复添加，但仍可完成移出；其他收藏夹、喜欢、评分与进度不变。浏览时改变排序不写回手工顺序。

人物合并先展示字段冲突、作品关联、来源身份和喜欢状态，用户指定目标及保留值；完成后旧链接转向目标，作品数去重。归档应显示影响，禁止用一个删除按钮同时删除资料和原视频。恢复遇到命名或关系冲突时让用户处理。

## 8 观看体验与个人整理

发现页优先显示真实可继续的观看记录，再显示最近加入与个人收藏。空库提供建库引导，零断点时不生成假续播卡。推荐只从已发布资料产生，保留旧“换一部”的轻量选片意图。

作品详情首先提供播放/继续、选集与版本，再显示故事简介、剧照、演员、系列、分类和其他资料。Web 和 Android 独立展示已有的简介与剧照，剧照按管理端维护的顺序浏览，可点开大图并返回影片原位置。打开详情不自动开始播放；用户可以先看资料。片商、标签、编号与来源放在资料区，文件路径放在技术详情，避免占据观看首屏。

喜欢影片、喜欢演员、收藏夹收录、评分、手动已看各自独立。评分可设置、修改和取消；未评分不是 0 星。已看标记可撤销，不自动把进度写成 100%。剧组与每集的个人状态分别维护，不能批量复制父项喜欢给全部子集。

返回列表保留分类、筛选、方向、页码和滚动位置；从影片进入演员、再进入另一部影片，应能逐层返回。Android 保留原有全屏、返回和前后跳转的使用意图，不以网页视觉稿替代原生播放验收。

## 9 筛选与排序必须完整承接

所有完整影片列表采用共同规则：片库、演员作品、系列成员、收藏夹成员、分类作品、喜欢、搜索结果、历史、管理作品。演员/系列/收藏夹详情的固定范围不能被“清除筛选”解除。首页有限书架、来源候选与选集列表使用各自语义顺序。

### 9.1 影片筛选

| 条件 | 用户能表达的查询 | 依据与边界 |
| --- | --- | --- |
| 搜索与分类 | 名称、编号、演员/导演；一个分类及后代 | 旧名称/分类/关系检索；双名称保留 |
| 分辨率 | 4K+、1080p、720p、576p 档、480p 档、更低、未知 | 保留旧细分意图；改用默认版本真实视频高度，分界见查询规格 |
| 中文标记 | 全部、支持、不支持、未知 | 沿用旧标记，区别字幕轨道 |
| 发行时间 | 指定年份、年份区间、完整日期区间、未知 | 旧 API 已有日期范围；只有年份的作品不能伪造具体日期 |
| 我的评分 | 最低分、最高分、分数区间、仅未评分、区间包含未评分 | 恢复旧上限和包含未评分；最低分只是其中一种用法 |
| 喜欢与已看 | 是否喜欢、是否手动已看 | 个人状态；不以播放次数推断已看 |
| 播放记录 | 次数上下限、从未播放、最近播放 | 旧播放次数字段与排序有明确去向；历史累计和新会话分开解释 |
| 入库时间 | 日期区间、入库至少 N 天 | 恢复旧 olderThanDays 的找片意图；按统一服务端时间计算 |
| 体积与时长 | 独立上下限或区间 | 旧接口有范围；按默认版本各段聚合，单位明确 |
| 关联资料 | 演员、系列、收藏夹、标签、片商 | 同一条件首版单选，不同条件取交集 |
| 形态与文件状态 | 电影/组/集/视频；在线、缺失、未知、不适用 | 资料与文件分开；离线仍可浏览 |

不同条件之间 AND；评分范围是否包含未评分使用显式选项。指定年份与年份区间互斥；完整日期范围启用时仅匹配有完整日期的资料，并显示提示。上下限颠倒、负体积、非法日期在提交前提示，接口也独立校验。

播放次数继续保留，不能因为清理模块后置而取消。展示为“历史累计 + 新系统有效播放会话”，历史数值不能证明旧完播次数；新会话以实际起播后的一次会话计数，暂停、心跳、重试不重复计数。具体去重和聚合见数据库补充设计。旧进度仍不迁移。

### 9.2 排序字段

| 列表 | 排序字段 |
| --- | --- |
| 影片 | 入库时间、发行时间、名称、我的评分、播放次数、最近播放、时长、体积；喜欢列表支持喜欢时间 |
| 演员 | 名称、创建时间、片库作品数、喜欢时间；筛选含分类、性别、喜欢、是否有作品 |
| 系列 | 名称、创建时间、片库作品数；筛选含分类、是否有作品 |
| 收藏夹 | 名称、创建时间、作品数 |
| 系列或收藏夹成员 | 上述影片排序，加手工顺序、加入时间 |

每项提供明确升序/降序。默认片库按最近入库，演员作品按发行时间倒序，系列/收藏夹成员按保存顺序；用户可切换。未知值固定最后，同值用稳定身份排序；作品数为 0 是有效值。成员浏览排序不会改变保存顺序，整理顺序时显示完整成员集合。

Web 观看端以海报为主，管理端影片资料库默认横图，可切换海报和表格，保留批量能力。移动端常用筛选在面板前部，较少使用的日期、体积、时长、次数条件折叠在“更多条件”，功能与其他端同义。分页、返回恢复和空值规则详见[列表查询规格](list-query-spec.md)。

## 10 播放与继续观看

用户点击继续播放后，必须先定位到对应作品/集、版本、文件段和毫秒位置，确认实际定位成功再起播并保存。加载失败不得把原断点写回 0；接近片尾不能仅按 90% 或 95% 判定结束。切换版本读取该版本断点，不直接复制位置。

Web 与 Android 保留播放/暂停、拖动、前后跳转、全屏、音量与选集；真实音轨/内封字幕按客户端能力呈现。无可用音轨、编码不支持、硬盘离线分别说明。首版不以 MKV 扩展名承诺全部浏览器兼容，也不假装进行了转码。

一个默认个人资料可以有多个设备。较新的播放会话接管后，旧设备延迟上报不能覆盖当前进度。退出播放器、断网重连、后台恢复都要验收。细则以[播放规格](playback.md)为依据。

## 11 来源 任务与运行设置

来源配置与资料编辑分开。JavDB 和现有补充来源的搜索、详情、人物、图片能力由适配器提供；新增来源复用同一候选/提案/接受流程。首版不做第三方插件市场，但不能把 JavDB 专用 Cookie 表单写进通用草稿模型。

任务中心显示扫描、探测、抓取、图片获取、演员补全及发布任务的阶段、成功/失败/跳过项、原因和重试入口。取消只停止未完成工作，已保存草稿和已发布结果保留；暂停和取消分别呈现。重新抓取仅更新候选，演员补全也不自动覆盖正式资料。

管理系统设置包括媒体根、挂载状态、来源出站连接、备份和服务版本。媒体根离线时保留资料和上次文件信息，盘恢复后重新核验；不能将一次空扫描解释为全部删除。FFprobe 随受控运行产物提供，超时或失败能单项重试。

Android 保留服务器地址编辑、测试连接、保存/恢复默认、缓存大小与清除、版本信息。更换服务器先提示账号/资料库归属变化，不能把旧服务器的待上报进度提交到新库；清缓存不等于删除个人状态或原视频。

Mac 登录后自动恢复需包含服务、数据库、任务和媒体挂载依赖。上线前验收备份还原、失败发布回退、外盘延迟挂载和出站网络失败恢复，不以进程启动成功代替可用。

## 12 数据模型与界面的对应规则

| 产品行为 | 主要数据 | 首版模型处理 |
| --- | --- | --- |
| 可编辑草稿与批次 | import_batches、import_items.draft、import_item_files | 草稿保存完整资料和临时关系；定义版本化结构，不写入正式片库 |
| 人工确认后再发布 | 草稿 revision、确认人/时间/确认版本、发布幂等键 | 补齐确认凭据；任何实质变更使确认失效，发布重校验 |
| 正式作品与文件分离 | media_items、editions、edition_parts、media_files、media_streams | 资料人工维护，文件事实探测；不为 UI 字符串重复建列 |
| 修改共享关系 | people/credits、franchises/franchise_items、categories、tags、organizations | 稳定身份、多关系唯一约束；分类仍为单归属 |
| 图片上传及替换 | assets、media_images、人物/系列/收藏夹封面引用 | 完成资源接收后才切换引用，失败保留旧图 |
| 来源与手工值 | source_records、快照、field_state、relationship_sources、change_sets | 原始快照不改写；接受和锁定有明确作用范围 |
| 个人状态与收藏夹 | user_media_state、user_person_state、collections/collection_items | 和资料保存分开；空评分与未知喜欢时间可表达 |
| 播放次数与断点 | legacy_play_count、playback_sessions/events/progress | 历史累计保留，新有效会话去重；旧断点不迁 |
| 排序与计数 | 上述表的查询投影 | 不新增“筛选表”；数量、默认版本体积等按统一口径计算 |

候选模型已经覆盖多数业务；这不等于所有字段和流程已实现。本轮补充应优先解决确认状态、草稿完整性、查询口径和清空语义。正式 migration 仍须裁剪后置表列，不能按 58 张候选表一次全量施工。详细变更见[产品与数据库承接设计](database/product-reconciliation.md)。

## 13 交付顺序与验收

具体开工清单、M0～M6 交付物、43 项旧能力归属和产品决定时点见[实施步骤与验收](delivery.md)。

先完成一条真实闭环，再扩展批量与复杂结构：选一个文件 → 完整编辑 → 确认发布 → Web/Android 找到作品 → 实际续播 → 修改正式资料 → 重新抓取并保留人工修改。随后覆盖分集、版本、批量、关系合并和运行恢复。

| 编号 | 验收任务 | 通过条件 |
| --- | --- | --- |
| P01 | 无来源手动录入 | 可填写完整资料并保存草稿；不强制有编号、演员、封面；有合法文件时可人工发布 |
| P02 | 修正抓错资料 | 更换候选、移除临时演员、替换系列；已编辑字段保留，保存后重新确认 |
| P03 | 草稿跨会话继续 | 换浏览器仍找到服务端草稿；失败输入不丢；发布重复点击不重复创建 |
| P04 | 更新正式资料 | 修改简介不影响喜欢/评分；清空可空字段和关系能够真实生效 |
| P05 | 图片与演员补全 | 上传/获取失败保留旧图；人物补全产生可接受/拒绝提案 |
| P06 | 上下部与多段 | 从列表勾选创建容器、选择资料来源、预览集顺序；取消不改草稿，解除保留各集； 两集各自续播；同集两段按段播放；不能混用编号或重复统计 |
| P07 | 新版本与文件改绑 | 保留作品身份和个人状态；文件变化先提示；默认版本聚合一致 |
| P08 | 完整筛选排序 | 三端条件和升降序同义；评分上限、入库天数、576p/480p、次数均有去向；空值与分页正确 |
| P09 | 关系与收藏夹 | 演员双名可搜、人物合并不重复；收藏夹移动不丢成员；浏览排序不写回 |
| P10 | 分类隐藏 | 本级及后代有影片时提示；取消保留编辑；隐藏后全部/搜索仍可找到 |
| P11 | 实际继续播放 | 正确集/版本/段定位后起播；95% 未结束仍能继续；失败不覆盖断点 |
| P12 | 运行与迁移 | Mac 登录恢复；盘离线不删资料；旧任务/进度不迁；备份可恢复 |

每个验收项同时检查需求、界面、数据、API 和失败情况。HTML 能点击只证明流程可评审；真实媒体、服务器持久化、并发与恢复必须在实现阶段另行验收。
