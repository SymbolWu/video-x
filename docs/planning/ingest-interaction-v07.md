# 录入列表核对与分集容器交互

下载箱选文件、草稿目标目录与手动移动发布的设计见[文件整理补充](storage-intake.md)。下文的资料核对、分集与版本规则同样适用。

2026-11-17 · 产品需求 1.1 · 原型 V0.7

录入以批次结果列表为主要工作区：先看到抓取了什么、还缺什么，再按需修改。完整编辑器负责补充和修正，不作为每一条入库的必经页面。创建分集直接使用列表中已经勾选的视频，不跳转到另一个页面重新选择。

V0.6 的主要问题是：列表只剩文件和状态，缺项藏在详情；勾选被限制为已确认条目，分组却需要在确认前进行；另一个“批量整理”页面要求重新选择，创建后也没有足够明确的父子展示。

## 2 结果列表直接显示什么

| 区域 | 默认显示 | 按需展开或编辑 |
| --- | --- | --- |
| 作品身份 | 封面缩略图、标题、编号、本地文件名、容器或集号标记 | 完整路径、编号和文件绑定维护 |
| 演职员 | 演员姓名、导演；空值明确写“无演员” | 完整人物关联、替换、新建、顺序 |
| 分类与系列 | 单主分类可直接修改；关联系列名称 | 标签、片商和其他关联在行内预览或完整编辑维护 |
| 日期与中文 | 年份或完整日期，未知有明确显示；中文支持/不支持/未知 | 日期精度与中文资料标记编辑 |
| 获取结果 | 正在获取、已返回结果、获取失败、手动资料 | 错误原因、来源候选、重试、逐字段采用 |
| 资料缺项 | 缺封面、缺演员、缺日期、缺简介、未分类等具体项 | 点击行内预览直接看简介和文件；无需离开列表 |
| 人工确认 | 待核对、已人工确认、已发布 | 可逐条核对，也可选择多条一次核对 |

“常用项齐全”只表示标题、封面、演员、发行日期、简介和分类六项有值，不代表抓取匹配正确，也不表示所有可选字段齐全。系列、标签、片商和编号可以合理为空。不同资料类型的检查建议可在后续评审中调整，不把这些建议做成发布必填规则。

三个维度独立：获取成功不保证有资料；资料齐全不等于人工已确认；有非必填缺项不等于禁止发布。无标题、文件绑定无效、探测/文件问题、分集结构不合法等发布阻断另行提示。获取失败的条目仍可手填后核对；运行中的任务须先稳定其结果。

列表提供全部、资料缺项、发布阻断、获取失败、已确认、已发布筛选，以及片名/编号/演员/文件搜索。父子组中只有子集命中时，仍显示容器作为上下文。筛选不会自动清空已选项，操作栏明确提示当前范围之外的选择数量。

## 3 勾选 核对 发布

1. 待核对条目可以勾选，用于分组、批量分类、重试或批量核对；勾选本身不代表已确认。
2. 点击“核对并确认所选”，在同一页面的汇总面板查看本次集合的封面、标题、演员、分类、日期、编号、来源、简介和文件；具体缺项与阻断原因并列显示。
3. 用户明确点击“确认这些资料”，记录当前草稿版本的人工确认。非必填缺项可接受现状，无需逐个打开编辑器，也不需要额外为每个缺项打勾。
4. 点击“发布所选”后再次展示将入库的集合。只要所选有未确认或有阻断的条目，就不偷偷过滤后发布其他项；用户先处理或调整选择。
5. 修改分类、资料、来源选择、文件或分集结构后，涉及条目的旧确认失效；重新获取只产生候选，不覆盖人工资料，不自动确认或发布。

“更多整理”保留统一分类和重新获取所选视频；只作用于明确选中的条目，容器不执行在线获取。

批量操作仍有明确的人工决定，但不把“逐条打开页面”当作人工确认的证据。大批次实现时需要分页与虚拟列表，确认摘要显示完整选择范围和阻断计数；原型使用有限样本。

## 4 选择视频创建分集容器

正常路径是：勾选上部/下部视频 → 点击“建立分集组（创建容器）” → 填写容器名称、选择资料取自哪一集 → 预览并调整顺序 → 点击“创建容器并关联 N 集”。

创建面板直接显示容器封面、演员、分类、简介，以及缩进的“第 1 集、第 2 集……”和对应文件。默认按当前所选条目在列表中的顺序排列；可以上移、下移并设置起始集号，序号根据预览重新生成。不会根据文件名中的 Part/CD 自动决定结构。

| 事项 | 规则 |
| --- | --- |
| 可选视频 | 至少一条独立且已绑定文件的未发布草稿；不能选入另一个容器或已经分组的集 |
| 容器资料 | 明确选择一条作为复制来源，再独立填写容器名称；复制封面、简介、演职员、发行日期、分类和关联 |
| 不复制的内容 | 视频版本和文件、作品编号、来源身份、个人喜欢/评分/断点；容器没有可播放文件 |
| 各集保留 | 原标题、编号、封面、演员等资料与全部版本文件；只新增父项关系和集号 |
| 资料暂缺 | 可以先组建容器，缺项随后补；缺文件不能作为可播放分集选入 |
| 创建后的列表 | 同一列表立即展开“容器 → 第 1 集 → 第 2 集”；显示各自缺项，不把父项完整度冒充子集完整度 |
| 后续核对 | 创建后选择范围包含容器和所选各集；一起核对、一起发布，避免漏选容器 |
| 取消 | 不创建容器，不修改任何所选草稿或集号 |

容器和系列是两种关系。创建上下部容器不会创建一个新系列；可以保留所选资料原有的系列关联。同一集的多个物理文件段仍进入“版本与文件”，不使用分集容器。

## 5 调整与解除分组

容器行提供“展开/收起分集”“核对整组”“调整分集”“解除分组”；子集也可直接核对整组，无需重新逐条勾选。调整面板展示当前完整顺序，保存后容器及各集重新核对；浏览或收起分组不改变顺序。取消调整保留原状态。

解除分组前列出受影响成员：移除未发布的容器草稿，各集恢复为独立视频，资料和文件仍保留，原确认失效。有已发布成员的组不能通过这个草稿操作解除，应进入正式资料维护流程。

勾选容器会选择它的全部未发布分集，操作栏显示实际草稿数量；取消容器勾选也取消这些成员。只选一个未发布组的子集不能绕过整个结构进行确认或发布。正式实现须在同一事务校验父子集合、集号、草稿版本和文件事实。

## 6 数据模型承接

| 页面内容或操作 | 数据依据 | 是否新增数据库字段 |
| --- | --- | --- |
| 列表实际值与缺项 | import_items.draft；发布后对应 media_items、credits、media_images 等 | 否；按当前草稿计算，不存固定完整度百分比 |
| 获取结果与失败 | import_items.execution_status/error_code/error_details、tasks/task_items | 否；任务结果与草稿内容分别解释 |
| 人工确认 | draft_revision、reviewed_revision/at/by | 否；复用 v0.5 确认凭据 |
| 待发布容器与分集 | draft 中临时父 ID、kind、episode_number；发布映射为 media_items.parent_id | 否；容器无 editions，各集独立拥有版本 |
| 拷贝容器资料 | 草稿中的明确字段复制与操作记录 | 否；不把相同来源身份同时绑定到父子作品 |
| 多版本与文件段 | import_item_files.edition_key/part_no；发布后 editions/edition_parts | 否；集序号不等于物理段号 |
| 勾选与展开收起 | 当前批次页面状态 | 否；不为列表选择或显示偏好新建业务字段 |

新交互无需扩表。候选库继续为 58 表、568 列、127 外键；现有 79 项数据库约束验证结果不因前端调整而变成新增验证。

## 7 本轮验收与边界

- 不打开完整编辑器，也能看到实际演员、日期、分类、文件和具体缺项；可筛出缺项，行内查看简介。
- 未确认条目能勾选和组成分集；但不能直接发布。
- 选择上部/下部后，能在一个面板看到容器来源、名称、文件与集顺序；创建、取消、调整、解除都有明确结果。
- 可在列表汇总确认整个组；非必填缺项不强迫补齐；结构不完整、旧确认或草稿变更不能通过发布。
- 容器不复制文件或编号，各集的原始资料与文件不因组建、排序或解除而丢失。

本轮原型演示上述路径；真实来源字段覆盖报告、全部列设置、跨页批量操作、向已有容器追加新分集、正式资料的拆组与变更事务仍需后续实现。它们保留在完整需求中，不因当前原型未覆盖而取消。测试与截图使用虚构条目，不操作旧系统或磁盘媒体。
