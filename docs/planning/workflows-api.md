# video-x 业务流程与接口规格

本规格把[产品体验](product.md)中的任务落实到用例、状态变化、接口和失败恢复。路径为拟定的 `/api/v1` 契约草案，正式工程再生成 OpenAPI；现有系统接口保持原样。

## 1 接口与模块约定

观看、管理和 Android 共用 server 用例层。浏览接口读取已发布且有效的资料；个人接口由会话确定 profile；管理接口需要管理员操作能力。首版一个个人账号可同时具备这些能力，不建设通用权限配置系统。

| 模块 | 拥有的数据和用例 | 与其他模块的协作边界 |
| --- | --- | --- |
| catalog | 作品、人物/详细名称、演职员、系列、分类、标签、归档与关系整理 | 不自行扫描文件、发起 HTTP 抓取或处理个人断点 |
| library | 根目录、文件、探测结果、可用状态 | 返回文件事实，不决定作品身份 |
| ingest | 批次、导入项、候选选择、复核、幂等发布 | 调用 catalog 和 library 的公开事务用例，组成一次发布 |
| metadata | 来源配置、快照、差异、锁定和适配器调度 | 提供候选和变更提案，由 catalog 用例校验并应用 |
| personal | 作品/人物喜欢、个人评分/已看、收藏夹 | 收藏夹操作不改作品元数据；按 profile 隔离 |
| playback | 播放方案、会话、进度与历史 | 使用 catalog 和 library 的只读查询，更新个人观看状态 |
| identity | 登录、设备与会话、管理员能力 | 客户端不能通过传入 profile_id 获得其他资料权限 |
| platform | 数据库、队列、出站 HTTP、媒体子进程、日志与审计 | 提供技术能力，不包含人物合并等业务规则 |

所有创建/发布/合并等可能重试的命令支持 `Idempotency-Key`。幂等记录以账号、命令范围和 key 唯一，保存请求摘要及结果；同 key 不同内容返回冲突。编辑与有序关系提交 `expectedRevision`，冲突保留用户输入并提示重新加载差异。schema 中数字、日期、枚举与空值必须和 Kotlin 客户端一致。

成功返回资源、revision 和 requestId；列表返回 items、page、pageSize、total，稳定排序并限制 pageSize。失败使用非 2xx 状态和 `{error:{code,message,details},requestId}`。建议 400 表示请求格式错误，401/403 表示会话/能力问题，404 表示资源不可访问，409 表示重复或版本冲突，422 表示业务规则不允许，503 表示依赖暂不可用。UI 根据 code 决定操作，不能解析中文 message。

## 2 人物浏览 维护与合并

### 2.1 从影片进入人物

1. 作品详情返回有序 credits，包含 personId、姓名、头像和职责；用户点击演员卡片。
2. 人物详情先展示概览和片库内作品数，再请求分页作品列表；默认取全部已入库参演作品，分类作为可选筛选。
3. 用户收藏人物时写入个人状态；取消收藏不影响任何参演关系。
4. 返回作品或片库时恢复原路由、筛选和滚动。详情请求失败显示重试，不能复用“没有作品”的空状态。

| 接口草案 | 用途 |
| --- | --- |
| `GET /people?role=actor&q=&categoryId=&page=` | 片库演员视图；常用名、详细名称与来源编号检索 |
| `GET /people/{id}` | 人物概览；合并源返回 canonicalId，客户端替换为目标地址 |
| `GET /people/{id}/media?categoryId=&watched=&sort=&page=` | 去重参演作品与同口径 total |
| `PUT /me/people/{id}/favorite` | 设置喜欢状态，重复设置结果一致 |
| `GET /me/favorites?kind=person` | 收藏页的人物视图 |

### 2.2 在资料维护中编辑

管理员从演员表或作品关联面板编辑。字段保存与关联整理分别提交，长表单失败保留输入；新增人物成功后回到原来的选择器并选中新人物。姓名修改不触发任何 ID 或演职员外键更新。

`POST/PATCH /admin/people[/{id}]` 创建或编辑资料；`PUT /admin/media/{id}/credits` 更新有序演职员；归档与恢复用独立命令 `/admin/people/{id}/archive`、`/restore`，避免用户误以为删除原视频。头像上传经过资源接口校验 MIME、体积、尺寸并生成受控 assetId。

### 2.3 合并重复人物

`POST /admin/people/{id}/merge-preview` 接收 targetId，返回字段差异、关系影响、收藏影响和双方 revision。用户选定保留字段后，`POST /admin/people/{id}/merge` 提交相同目标、选择、revision 和幂等键。

| 情况 | 用例行为 | 页面反馈 |
| --- | --- | --- |
| 名字相同，来源身份不明 | 只提示候选 | 用户比较后选复用、新建或合并 |
| 同作品同职责重复 | 合并同职责关系与来源依据，作品只计一次；角色名后置 | 预览显示去重数量 |
| 头像/常用名/详细名称/分类冲突 | 展示并选择目标；人工锁定默认保留 | 不在确认后再隐式选值 |
| 来源身份无法迁移 | 整个命令失败并回滚 | 显示需处理的来源冲突 |
| 任一人物 revision 已改变 | 返回 409 REVISION_CONFLICT | 保留目标选择，重新加载预览 |
| 请求结果未知而客户端重试 | 用同一幂等键返回已有结果 | 不再次执行或生成第二个人物 |

保存成功后使人物、作品演职员、人物收藏、检索与分类计数失效。无 WebSocket 时在路由重新进入、窗口重获焦点时检查数据；不要假设打开的另一个客户端已收到实时推送。

## 3 系列与收藏夹

| 接口草案 | 用途与约束 |
| --- | --- |
| `GET /franchises`、`GET /franchises/{id}`、`GET /franchises/{id}/items` | 系列列表、概览和分页成员 |
| `POST/PATCH /admin/franchises[/{id}]` | 资料、封面与主分类 |
| `PUT /admin/franchises/{id}/items` | 有序成员替换，带 expectedRevision；完整列表禁止漏传 |
| `GET /franchises/{id}/next` | 按个人断点和已看状态返回建议作品及原因，不自动起播 |
| `GET/POST /me/collections`、`GET/PATCH /me/collections/{id}` | 收藏夹查询、新建与编辑；名称规范化后检查冲突 |
| `POST /me/collections/{id}/items` | 追加成员，已存在的跳过，保留原有顺序 |
| `POST /me/collections/{id}/remove-items` | 批量移出，不修改其他收藏夹和喜欢 |
| `PUT /me/collections/{id}/order` | 发送全部有效成员 ID 及 expectedRevision；成员集合必须一致 |
| `POST /me/collections/{id}/archive`、`/restore` | 归档与恢复，返回受影响成员数；作品保留 |
| `PUT /me/media/{id}/collection-memberships` | 作品的多收藏夹选择面板；与喜欢状态独立 |

作品的多收藏夹面板读取当前 membershipsRevision；确认时事务内应用差集，仅修改当前作品的成员关系，更新受影响收藏夹的 revision 与该作品 membershipsRevision。所有收藏夹成员变更用例同时维护这个版本，避免另一端的选择被覆盖。管理端收藏夹入口复用当前 profile 的个人用例。

系列详情的播放动作先查询建议作品，再使用统一 playback 建立会话。首版不跨不兼容版本自动续播。收藏夹默认按自定义顺序查看，选择其他展示排序不会改写保存的顺序；整理模式回到自定义顺序。

### 3.1 个人评分

`PUT /me/media/{id}/rating` 接收 `{rating: 1..5}` 或 `{rating: null}` 与 `expectedRevision`；profile 由会话确定。`null` 表示取消评分，0 和小数均拒绝。返回最新 rating、个人状态 revision 与 requestId；同值重试不创建评分历史。

作品详情点击星级可设置/修改，使用明确的“取消评分”动作清空；片库支持最低评分/未评分筛选与评分排序。保存失败保留所选值并允许重试。评分属于作品，不随播放版本切换改变，不自动喜欢、不加入收藏夹、不改已看或播放次数。首版不增加评分历史表，网站评分候选表不参与此用例。

## 4 分类范围与结构维护

作品、演员各属一个分类。`GET /media?categoryId=&includeDescendants=true&page=` 按作品分类筛选，`GET /people?role=actor&categoryId=&page=` 按演员自身分类筛选；不传 categoryId 表示全部。演员作品列表的 categoryId 筛选作品归属，不改变演员分类。喜剧片、动作片等是用户维护的分类名称，不要求 genreId；首版不支持一次选择多个分类。

观看端使用 `GET /categories/tree` 获取有效且可见的导航树，父节点隐藏时导航中隐藏整条分支。`GET /categories/{id}` 和 `/media`、`/people`、`/franchises` 返回落地页资料及同口径列表。隐藏节点可由已有链接打开，页面说明其不在分类导航显示；作品的全局搜索仍可找到。

管理端接口包括 `POST/PATCH /admin/categories[/{id}]`、`PUT /admin/categories/order`，以及 `POST /admin/categories/{id}/migration-preview`、`/migrate-and-archive`。迁移预览返回 directCounts、subtreeCounts、提升的子分类、目标分类和树 revision。确认时树已变化则重新预览。

显示开关另提供 `POST /admin/categories/{id}/visibility-preview`，返回目标状态、本级影片数、含全部后代影片数、是否需要提示及预览标识。显示→隐藏且影片数非零时，前端提示数量，用户可取消或继续；零部直接保存，隐藏→显示无需该提示。分类编辑与列表快捷开关均走此规则，不另设绕过提示的写路径。

既有 PATCH 在 expectedRevision 之外携带本次隐藏确认及预览标识，服务端保存时重新核对分类范围与影片统计；需要提示但尚未确认、或预览已变化，则返回可处理的 409 CATEGORY_HIDE_CONFIRMATION_REQUIRED 和最新预览。确认后允许隐藏非空分类。范围变更与统计核对按分类事务锁协议执行，相关发布/改类写入需遵守同一约定，应用集成阶段验证；不依赖客户端缓存计数。统计以观看列表中已发布未归档作品为准，包括离线作品和已隐藏子分类，不含导入草稿，不重复累计版本/文件。操作只改变导航可见性，不改变作品归属和搜索结果。

分类移动与迁移共享层级锁；禁止把节点移动到自身或后代。树结构、归属更新和归档在同一事务提交，避免中途失联。排序列表只包含同一父级下的兄弟节点，不能通过拖拽排序隐式改变父级。

## 5 从文件到可观看作品

### 5.1 导入项状态

导入使用“资料阶段”和“执行状态”两个字段，避免将匹配失败、等待确认和批次暂停混进一串线性状态。

| stage | 已持久化的事实 | 下一步 |
| --- | --- | --- |
| discovered | 根目录身份、相对路径、stat 及文件引用 | 限流执行探测 |
| probed | 文件容器与轨道事实；失败记录独立保存 | 匹配来源，或选择仅用本地资料 |
| matched | 候选、匹配依据和选定快照 | 复核身份、关系、版本/分段归属和字段差异 |
| ready | 发布所需资料有效，人工阻断项已处理 | 等待人工确认并点击发布，不自动推进 |
| published | 作品、版本、关联与发布结果已提交 | 在观看端查看，后续更新走资料刷新流程 |

执行状态使用 queued、running、waiting_user、retry_wait、failed、cancelled、completed；批次另有暂停标记。重试从最后已完成阶段继续，不清空已选候选和人工输入。阶段允许显式退回重选，已发布后不退回草稿。

### 5.2 入库工作台路径

1. 选择已经登记的根目录，扫描器核验根标识，发现文件并增量探测。关闭页面不影响任务执行。
2. 显示新增、已知文件、可能重复内容和缺失文件的不同结果。快速指纹相同只产生候选，不自动删除副本。
3. 平台按来源能力检索或读取本地资料，展示匹配依据；用户可以改候选或仅使用本地资料。
4. 用户选择创建作品、增加已有作品的版本、追加文件段或关联真实分集。分段与分集的例子在面板中说明，不让用户仅靠父码猜测。
5. 预览人物、系列、分类及字段变更；复用已有身份，新增人物和系列可在选择器内完成。批量应用分类有独立预览。
6. 人工核对后对 ready 项点击发布，也可主动选择多项批量发布；某项失败保留其余项结果。成功后提供“查看作品”，观看端立刻读到对应人物、系列、分类与版本。

接口草案为 `POST /admin/import-batches`，`GET /admin/import-batches/{id}`，`GET/PATCH /admin/import-items/{id}`，`POST /admin/import-items/{id}/match`、`/prepare`、`/publish`，以及批次 `/pause`、`/resume`、`/retry-failed`、`/cancel`。批量 publish 返回受理任务和逐项结果入口，不能以请求已入队当作入库成功。

publish 必须由用户显式发起，提交幂等键、已核对项的 expectedRevision 和所选 candidate/snapshot 身份；服务端重新检查归属及版本。批量命令仅覆盖这次人工选中的确定集合，草稿或候选变化返回冲突并等待复核。首版无 autoPublish 配置，扫描/抓取成功不能调用自动发布路径；已授权发布任务可以幂等恢复同一决定。已入库资料刷新只生成差异提案，人工接受后才应用。

批次暂停后不领取新项，正在处理的项允许完成当前可保存阶段。取消发出 AbortSignal，停止后续副作用；取消发生在发布事务已提交后，以 published 结果为准并向用户说明。数据库事务内不等待外网或移动原文件。

## 6 来源适配器与任务恢复

适配器声明 search、details、person、artwork、local-sidecar 等能力，平台仅调用已声明的方法。在线来源以 providerId+externalId 定位，本地 NFO 为后置扩展，启用后以受控 fileId 定位，不必伪造一个在线检索步骤。

ProviderContext 提供受控 HTTP、来源凭据引用、日志、取消信号和按 fileId 读取允许的旁车资料的接口。适配器不能读取任意宿主路径、直接写 ORM 或下载到最终资源目录。在线解析与本地解析都返回统一资料提案。

| 失败类别 | 重试与恢复 | 用户看到的动作 |
| --- | --- | --- |
| DNS、代理不可达、超时 | 有上限的退避；保持阶段结果 | 检查出站连接 / 重试 |
| 429 或站点暂不可用 | 尊重 Retry-After 并降低并发 | 等待至指定时间 / 暂停来源 |
| 凭据过期 | 暂停该来源的新请求 | 更新授权后只重试受影响项 |
| 需要人工验证 | waiting_user，保留任务与候选 | 由用户处理验证后继续 |
| 页面结构变化 | 禁止盲目重试；标记解析器版本 | 暂停来源并修复样例与解析器 |
| 没有匹配结果 | 进入人工核对，不当作网络故障 | 手动搜索 / 本地资料入库 |

队列按可能重复投递设计。业务任务保存 itemId、已完成阶段、最后结构化错误、结果和 queue_job_id；队列拥有 attempt、next_run_at 与 lease 等运行状态，worker 失联后由队列回收租约。每步保存检查点，外部请求和图片下载有独立幂等标识。outbox 与业务结果同事务，投递重复不重复发布；不再另建一套进程内调度器。

导入任务与演员补全复用任务基础设施，采用不同任务类型和处理器。任务页可从失败项回到对应影片、人物或批次；用户无需依靠任务 ID 处理日常入库。

## 7 播放与断点

详细契约与真实播放器验收见[观看进度与继续播放](playback.md)。旧进度不迁入，新系统初始化无断点、无播放会话或事件，喜欢/评分等仍保留。

客户端提交设备能力和 play/resume/restart 意图请求 `POST /playback/plans`，服务端解析具体集、版本、文件段和毫秒位置，返回 direct/unsupported（remux 和转码后置）。`POST /playback/sessions` 使用幂等键，在事务中重查有效目标并固定 start_mode/start_part_id/start_position_ms，返回 sessionId、takeoverGeneration、target 和受控媒体 URL。创建会话不改断点、不计播放。

两端必须等待文件准备、完成目标定位并实际播放后发送 start；此前默认 0 的进度不得上报或入库。定位失败保留原断点，不静默退回从头。服务端接受 start 后才更新 resume_edition_id、进度与真实播放计数。首次定位验收容差目标为 2 秒。

播放事件通过 `POST /playback/sessions/{id}/events` 上报 seq、eventId、partId、positionMs 和事件类型；服务端校验归属、代数和递增序号。主动后退保留，旧设备迟到事件不夺回新设备的当前断点。客户端服务器时间漂移不参与优先级判断。

两端使用持久队列按序发送事件，仅合并相邻 progress；正常播放每 10 秒检查点，暂停/seek/离开立即保存。Web 不能只依赖页面关闭请求成功。断点写入失败提示待同步；旧会话被接管后不能用本地补发夺回进度。自然播完最后一段才写 completed_at，95% 等百分比不触发从头；手动已看独立。

服务端支持 HEAD、Range、后缀区间、越界和条件请求；Nginx 内部投递只服务鉴权后的 fileId。切换版本使用该版本自身有效断点或明确从头，首版不按比例跨剪辑估算位置。

## 8 前端状态与失败恢复

React 远程资料统一进入查询缓存；页面仅保存筛选、模式和暂存输入，关联事实由 API 返回。查询键包含分类范围、实体 ID、profile 和筛选，退出登录清理个人缓存。筛选写入 URL，可返回且可复现。

mutation 返回成功后更新当前资源并使受影响的列表和计数失效；冲突页面保留待提交变更，重新拉取后由用户确认重放。喜欢可以乐观更新并失败回退；合并、迁移、发布和归档先等服务端完成。

Android 将 DTO 映射为本地 UI 状态；网络失败、空数据和缓存数据分开表达。真实 API 的资料同步不能用原型的同源 localStorage 事件替代。跨端一致性通过 revision、幂等、重新查询和断点接管协议保证。

## 首版单账号与分集范围（2026-11-16）

账号、默认 profile、设备和会话按通用结构实现，首版不提供注册、多账号/多 profile 切换或公网账户管理。作品组详情按 episode_number 选集，上下部/Part 各自有播放版本；不强制季。组级继续观看查询最新子集状态，组本身不建立播放会话。生日、人物简介、角色名等后置，旧任务与结果 JSON 不进入导入流程。

## 10 列表契约补充 · V0.5

三端查询遵守[列表筛选与排序规格](list-query-spec.md)：按实体白名单校验字段、方向与条件，完整查询后分页，返回有效查询；空值固定最后，同值以 ID 收尾。成员浏览排序不调用顺序写接口。条件变化重置页码，缓存键包含方向、profile 及固定关系上下文。URL 中的演员/系列/收藏夹 ID 始终限制查询范围，清除筛选不能解除。
