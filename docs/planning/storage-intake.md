# 从下载目录整理到片库

**交互设计稿 · 2026-11-20**　[操作原型](../../design/2026-11-redesign/preview/storage-intake.html)

## 按现在的下载习惯操作

1. **从下载目录选择**。工作台记住下载箱 `WD_12T_DISK / Download`，直接显示当前层的文件和子目录。支持面包屑、返回上层、按名称筛选、多选 MP4/MKV，选择跨子目录保留。已进队列的文件可定位到原草稿。点击「加入录入队列」后服务端只探测选中的文件。整目录扫描保留为次入口。手工新建仍可不带文件，之后用同一选择器绑定。
2. **安排位置**。队列中每行保留片名、编号、原文件、来源返回与草稿缺项。文件下面增加「整理到…」。单条可点路径修改，多条可选「批量设目标」。目标选择器先选盘，再按实际目录逐层浏览。最近使用的位置可直达；显示盘上可用空间和当前文件夹计数。在下载箱中的文件初始为「待设目标」。已在正式资料目录的文件可明确选「保留原位」。下载箱本身不能作正式目标。建议可记住上次位置作为快捷项，只有用户点击应用后才写进草稿。
3. **核对**。草稿保存源位置、目标位置和预期文件名，不执行磁盘操作。核对摘要并排列出来源、目的地、文件名、大小、同盘或跨盘。分集容器没有文件；选容器统一设置时，把计划展开到每集的每个实际文件。每集可另选目录。修改文件、目标或资料会让旧确认失效。作品主分类、演员/系列分类与物理文件夹独立。
4. **手动发布**。确认页列出移动几份文件、涉及哪些盘、总量、同名或离线阻断。最终按钮「移动并发布 N 部」才提交任务；全部原位时显示「原位发布」。整组分集文件就绪才能对观看端可见。平级的独立影片以作品为单位返回成功或失败，部分完成时按作品展示，重试仅处理未完成的部分。
5. **完成**。队列展示最终路径，播放读取原有文件 ID 的新位置。手工保存草稿、抓取返回、采用候选、人工核对都允许中断并稍后继续。

例如从 `WD_12T_DISK/Download/样片.mp4` 选中一部影片，打开「日本 → pixelization-58」并应用，确认页显示 `WD_12T_DISK/日本/pixelization-58/样片.mp4`。另一部作品可去「欧美」或另一个盘。默认保留下载时的文件名。截图中的「日本」「欧美」「三级」「国产 AV」「动漫」是这块盘已有的目录，程序按实际目录读取。目录按自然数排序，允许通过「新建子目录」给下一组命名，系统不猜下一组编号。

## 50 个文件的旧规则

旧版选择目标时统计该目录直接包含的视频文件，前端将选中条数及计划写到该目录的草稿加上，超过 50 则拒绝。旧代码将已经拼了文件名的目标值与目录字符串比较，之前分配的草稿容易漏算。建议首版保留默认上限 50，可按整理位置调整或关闭。显示「已存 47 + 其他待移入 1 + 本次 2 = 50 / 50」。按实际文件计数，同一个计划不能重复计数，分集容器占 0，同目录原位占 0。改目标时释放旧占位。只数直接子文件中的受支持视频，不递归统计所有子目录。提交发布时重新校验目录和待执行计划，防止两次并发提交同时抢最后一个位置。

## 实现与恢复

| 数据与接口 | 设计 |
| --- | --- |
| 存储与目录浏览 | 复用 `storage_roots` 的卷标识，实际路径为 `root_id + relative_path`。每个根可有多个角色子目录，例如 12T 的下载箱和五个资料目录。Mac 用 /Volumes 路径，Docker 用明确的绑定目录，注册时对照盘标识。管理端凭根 ID 和相对目录只读列一层，排除隐藏项、符号链接和越界路径。8T 的可写范围由使用者登记。 |
| 草稿整理计划 | 用独立的逐文件记录关联 `import_item_files`，字段包括动作（原位/移动）、目标根、相对目录与文件名、源文件内容版本和计划版本。无文件手工稿允许没有计划。勾选写入时服务端锁定草稿、更新版本并撤销旧核对。多条批量设目标要么全部成功，要么返回逐条冲突供修改。 |
| 发布任务 | 发布命令用核对版本和幂等键创建持久任务、逐文件步骤与目标路径预留。在外部文件操作前写入日志。API 和播放服务只读；负责整理的 Worker 仅对登记的下载箱和目标目录有相应的写权限。Compose 现有单根只读配置保留作原位入口。 |
| 同盘 | 校验盘标识、源大小/时间与探测时一致、目标不存在或确为同一文件。使用文件系统支持的独占移动，遇到同名阻断，可改目录或目标文件名。不能安全独占提交时回报原因。人工确认前不建目录、不移动文件。 |
| 跨盘 | 检查可用容量，拷贝到目标盘任务专属临时文件，校验字节数与内容摘要，独占落成目标名。持久记录已验证结果后才更新正式文件位置并提交发布；其后确认源仍是原文件再清理。清理失败标记「已发布 · 源待清理」，重试清理前重新校验身份；目标未验证时保留下载源。 |
| 出错和重试 | 断电、拔盘、同名、空间不足、源在下载过程中变化均有逐文件状态。重启后按步骤和文件身份检查两边；已经移动成功的步骤不再复制。校验失败停在待处理，不默许按旧路径发布。中途一集失败，整组留在管理端；已就位的集显示实际位置，重试其余集。 |
| 保住播放与扫描一致性 | `media_files.id` 和 `edition_parts.file_id` 稳定；纯移动更新位置及目标文件事实，跨盘 mtime 与旧盘可能不同。播放、Range 请求与探测均按文件自己的根寻址。扫描器识别活动任务、临时文件、已预留目的地，避免再造一个条目或把正在移动的源标为丢失。 |

## 交付顺序与验收

| 顺序 | 可独立验收的结果 |
| --- | --- |
| 目录选择与计划 | 双盘定位、下载箱内逐层多选、手动草稿绑定、单条和批量定目标、新建目录预览、50 上限与原位例外。关掉管理端再打开，草稿和计划仍在，实盘零改动。 |
| 同盘移动与发布 | 在隔离样片卷验证同名保留、核对版本过期、两人次重复点击、目录达到上限、整组可见性与发布后播放。对照源、最终路径、数据库和播放断点。 |
| 跨盘与恢复 | 在两个不同文件系统测试复制中断、校验后断电、目标离线与源清理失败；重新登录/重启后逐步恢复，避免覆盖或删除未知文件。 |
| 实际盘接入 | 在上述测试通过后再登记实际两盘的下载与资料目录，验收一批用户选定的样片。 |
