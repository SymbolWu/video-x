# 三端原型与数据模型核对 · 2026-11-17

> V0.6 增加完整编辑、恢复遗漏筛选、演员资料补全和收藏夹复制/移动四组交互。最新范围以[PRD](product-requirements.md)、[旧能力清单](legacy-capability-baseline.md)和生成的 schema-audit 为准；下文早期缺口描述保留用于追踪。

本轮核对范围是总入口、Web 观看端、管理端、移动端，以及共享交互。依据是 [v0.5 候选模型](database/model-spec.json)、[逐字段来源](database/field-provenance.json)、[已确认范围](database/confirmed-scope.md)，不依照旧原型反向补造字段。没有修改旧系统数据库或业务代码；本轮另行修正候选 SQL，见数据库承接设计。

## 1 核对结果怎么理解

原型此前确实没有及时同步数据模型决定。它展示了已经取消或后置的业务，也遗漏了部分已确认能力。这轮同时修正了界面和对应的演示交互；下面的“已呈现”不等于已经接入数据库或完成正式产品。

| 登记结果 | 字段数 | 含义 |
| --- | ---: | --- |
| 已呈现 | 8 | 对应的界面流程有明确依据；仍使用虚构样本 |
| 部分呈现 | 182 | 有查看或操作入口，但功能相关的某些状态/写入尚未画完整；具体缺口逐功能注明 |
| 待补界面 | 31 | 必需的界面尚缺，或只有静态运行状态，不能算已覆盖 |
| 内部处理 | 297 | ID、关联身份、并发、幂等、扫描指纹、协议与审计等；无需用户逐列录入 |
| 后置 | 50 | 仅存在于候选定义，首版不要求展示/编辑 |
| 合计 | 568 | 58 张候选表中的全部字段均有处置，不表示 568 个字段都要上界面 |

交互核对表有 31 项功能登记，可按字段、旧字段、表、状态搜索，显示使用位置与现状。部分呈现保留为未完成项，不用“原型看起来能点”替代业务验收。

## 2 本轮修正

| 原问题 | 当前处理 | 字段或规则依据 |
| --- | --- | --- |
| 移动片库宣传标题、英文标语、说明占据大块首屏 | 片库采用紧凑标题、影片/演员/系列切换、分类按钮和搜索；移除宣传段落及重复搜索入口 | 产品布局，不需要数据库字段 |
| “所有类型”仍依赖独立 genre | 移除；使用同一分类范围选择器。移动端已看标记、评分、年份、中文资料标记置于按需筛选面板，排序与数量共用一行 | `media_items.primary_category_id`、`people.primary_category_id` → `categories`；`genres` 后置 |
| 8.x 网站评分与“评分最高” | 移除；增加我的 1～5 星评分与取消入口，排序使用个人评分 | `user_media_state.rating`；`metadata_ratings` 后置 |
| 播放超过 90% 就当作已看/不再续播 | 已看改为手动标记；续播与真实模拟完播独立，不用 90% 阈值 | `watched_at` 与 `playback_progress.completed_at` 分开 |
| 原型仍读取旧百分比生成起播位置 | 新模拟记录按版本/文件段/毫秒保存，不读取旧 `vx-progress`；提供从头播放 | `edition_id`、`part_id`、`position_ms`；真实 seek 和服务端协议仍待实现 |
| 演员别名、简介、错误的资料编码 | 使用常用名与详细名称，分别维护和合并；不自动追加别名；人物/系列不再要求无依据的编码 | `people.full_name/detailed_name`；生日/简介后置；`people`、`franchises` 无 code 列 |
| 原始标题、排序标题、宣称时长、季号、剪辑类型、版本级语言误作为首版输入 | 遵守逐列后置标记，移除首版录入；时长来自文件事实 | 逐字段 `stage=后置`；分集首版优先 group→episode，不强制加季 |
| 备注、发行精度、中文资料标记没有维护入口 | 影片资料编辑补齐；观看端次级资料中呈现备注、发行和标记 | `notes`、`release_precision/year/date`、`supports_chinese`、`cover_layout`；中文资料标记不冒充字幕探测 |
| 标签只是写死文案/字符串，片商没有入口 | 管理端增加标签、片商字典与影片关联；标签按稳定 ID 关联，改名保留关系 | `tags`、`media_tags`、`organizations`、`media_organizations`；分类、属性组、隐藏分别维护 |
| 所有影片固定三个版本、固定大小、固定画质 | 版本/文件使用各自样本，不再把切换按钮冒充转码；可编辑版本名称/默认/备注，媒体事实只读 | `editions`、`edition_parts`、`media_files`、`media_streams` |
| 上下部/分集关系无入口 | 管理端“分集结构”提供类型、父项、集号；详情按关系展示分集；容器作品不能直接播放 | `media_items.kind/parent_id/episode_number`；不是文件段编号 |
| 匹配成功与人工确认混淆，未勾选时一键发布全部 | 准备资料、人工核对、明确勾选、发布确认分开；提交前重核草稿；修改草稿关联须重新确认；资料就绪不标成可入库，另计人工已确认数量；移除无依据的匹配百分比 | `import_items.stage/execution_status/draft/revision`；原型中的 reviewed 是草稿确认状态，不增设 SQL 列 |
| 导入修改直接污染正式样本 | 手动匹配和关联编辑写入草稿，不直接改已发布资料 | `import_items.draft` 与 `media_items` 分离 |
| NFO 与随便输入来源名就能添加适配器 | 首版只展示 JavDB、Havtw 的配置与启停，移除 NFO，列出已安装适配器 | `providers`、`provider_configs`；NFO 明确后置 |
| 已发布资料差异、字段锁定没有入口 | 增加一个简介差异的接受/拒绝/单字段锁示例 | `metadata_change_sets`、`media_field_state`；完整冲突处理尚未覆盖 |
| 账号信息全是固定文案 | 提供单账号显示名编辑；保留播放偏好 | `profiles.display_name/preferences`；初始化登录、设备撤销仍待补 |

观看端不承担字典维护。管理端进入作品资料、关联、文件及分集结构；移动端只展示消费所需内容，把完整资料折叠在详情中。分类隐藏确认继续保留：本级和子分类有影片时提示，取消保留输入，继续只隐藏入口。

## 3 仍缺哪些关键界面

以下是这次核对发现的真实缺口，不将它们描述为已经补完。后续继续原型设计时按此清单验收，不直接进入正式开发：

1. **媒体根配置与离线恢复**：当前系统页只是状态样本。还需库/根目录编辑、挂载标识、扫描开关、离线/错盘提示及恢复；对应 `libraries`、`storage_roots`。
2. **初始化、登录与设备会话**：不做多账号，但需要登录、失效重登、当前设备与会话撤销；密码哈希和 token 哈希永远不作为显示/编辑字段。
3. **版本和文件维护的完整流程**：新增版本、改绑文件、分段排序、文件离线/探测失败及多音轨选择；真实切换不能复制另一版本的断点。
4. **分集的完整编辑**：当前有关系表单，尚需连续示例、批量创建组/集、重排、跨父项移动和冲突；不把物理文件段自动识别为第几集。
5. **来源复核的完整流程**：候选切换、多来源冲突、来源身份链接、完整草稿、逐字段锁/接受/拒绝及并发变化；人物和系列的来源刷新尚没有完整页面。来源值映射本身仍属后置。
6. **作品、版本、标签、机构、库/根的归档影响及恢复**：现有归档恢复覆盖演员、系列、分类、收藏夹；其余不能因有 archived_at 就宣称已提供入口。
7. **图片托管与异常**：现阶段只切换本地演示头像/封面影片；上传、替换、多图、图片失败和恢复尚待补。

这些缺口分别登记在核对表的“部分呈现/待补界面”中；不需要为了填空再造新数据库列。

## 4 非数据库内容与验证边界

- 数量来自关联查询；GB、画质、进度条和剩余时间来自基础字段换算。
- 健康状态、连接测试、响应时间、容量、工具版本、容器恢复来自运行检测或部署配置，不因界面出现就增加持久列。现在全部为演示值。
- 媒体服务器地址是连接前的设备设置；搜索词、当前标签页、滚动位置是页面状态。持久播放偏好使用 `profiles.preferences`，其正式 JSON schema 仍需随接口约定。
- 首页选片和其他影片只是确定性取样，不表示首版已经有推荐模型或推荐表。
- 本轮不读取或迁移真实库；虚构的详细名称、轨道、日期、来源提案不能当作现有数据证据。
