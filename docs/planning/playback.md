# video-x 观看进度与继续播放详细设计 · v0.4

更新于 2026-11-16。用户确认旧客户端的继续播放存在缺陷，video-x 重新建立观看进度，不迁入旧断点。本文件是新系统的实现与验收契约，尚未接入播放器；没有据此宣称已经定位或修复旧客户端故障。

## 1 初始化与保留范围

- `movie.watch_progress`、`movie.last_play_position_ms` 不迁移，不换算、不创建迁移专用播放会话。旧库备份保留原始记录即可。
- 新库 `playback_sessions/events/progress` 初始为空；`user_media_state.resume_edition_id=NULL`、`takeover_generation=0`、`watched_at=NULL`。初始化后没有继续观看卡片，首次真实播放后才建立。
- 喜欢、评分、收藏夹与资料仍按原规则迁移。旧累计播放次数和最近播放时间仍可作为历史汇总保留，本次没有将它们一并清空；它们不能产生续播卡片、已看状态或伪造的新会话。父项镜像次数与子集次数不得重复累计。
- 文件大小从实际文件 stat 重读；离线文件保留待核验状态。历史喜欢为 true、喜欢时间为空的情况合法，新喜欢才写真实时间。

### 首版播放兼容范围（2026-11-17 确认）

MP4、MKV 是首批文件识别、入库与原生播放验收对象。首版播放方案仅 direct/unsupported；转码、服务端重封装（remux）列为后置，不为兼容问题修改原文件。

扩展名不作为“可播放”的充分条件。播放计划结合真实容器、视频/音频编码、客户端与设备能力判断；同一文件在 Web 和 Android 上可得到不同结果。文件有效但当前端不兼容时，资料可以人工发布，详情保留媒体信息并提示“当前设备不支持”，不建立虚假已开始会话或清空断点。文件损坏或无法完成基本探测则留在复核/失败状态。

跨端基础验收使用 MP4 + H.264 + AAC；MKV 和其他轨道组合按实际客户端分别测试。MP4/H.264/AAC 是广泛支持的组合，但容器与编码仍需分别判断，见 [MDN 编码指南](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Video_codecs)。Android 的容器解析与设备解码支持也分层，见 [Media3 支持格式](https://developer.android.com/media/media3/exoplayer/supported-formats)。这些是验收基线，不代表已测过用户当前媒体库。

## 2 用户看到的行为

| 场景 | 主操作与结果 |
| --- | --- |
| 尚未开始 | 显示“播放”，从所选版本首段 0 开始 |
| 有有效断点 | 显示“继续播放 · 32:15”；进入对应版本、文件段和位置 |
| 上下部 / 多集 | 显示“继续第 2 集 · 32:15”，由服务端返回实际集 ID，不能把父项进度套给第 1 集 |
| 接近结尾但未播完 | 仍继续真实位置，不按 90%/95% 等阈值自行归零 |
| 已自然播完 | 从继续观看列表移出；详情提供“重新播放”。有下一未完成集时提供“播放第 N 集” |
| 主动选择“从头播放” | 使用明确 restart 意图；真正从首段起播成功后才更新断点，加载失败保留原记录 |
| 拖动回退 | 保存回退后的真实位置；不能取历史最大位置代替当前断点 |
| 定位失败 / 文件离线 | 保留原断点，给出重试或明确选择从头播放；不能悄悄从 0 播放并标作续播成功 |
| 手动标记已看 | 更新 watched_at，不改变真实断点。取消已看也不恢复或清空播放位置 |

“播放完成”来自真实结束事件，“已看”是个人标记。两者独立。首版不增加自动已看阈值，也不把拖动到末尾直接等同于播完。

## 3 数据各自负责什么

| 数据 | 职责与写入规则 |
| --- | --- |
| media_files / edition_parts | 时长、可用性、版本内文件顺序和文件内容代数；不存个人百分比 |
| playback_sessions | 一次播放尝试、设备、接管代数、实际起播状态；新增 start_mode、start_part_id、start_position_ms，固定本次起播目标，供重试与故障追溯 |
| playback_events | start/progress/pause/seek/ended 的幂等事件；seq 是动作顺序，不按 position_ms 大小决定新旧 |
| playback_progress | 每个 profile+edition 一条最新有效段内毫秒位置；新增 completed_at，记录整个版本自然结束，NULL 表示当前未完成 |
| user_media_state | 当前接续版本、最近播放时间、接管代数；喜欢、评分和手动已看分别更新 |

会话起播模式为 fresh/resume/restart。fresh/restart 的目标毫秒必须为 0，且事务校验目标是首段；resume 使用服务端已保存的有效位置。start_part_id 通过复合外键保证属于会话版本，不接受客户端任意跨版本坐标。

百分比仅在已知时长时计算显示，不作为恢复输入。多文件版本显示总进度时累加前段时长；任一所需时长未知则显示时间而非伪造百分比。completed_at 只有最后一段自然结束才写入，中间段结束只推进到下一段；再次真实起播或有效 seek 后清空本次完成状态。手动 watched_at 不自动变化。

播放计划必须校验文件在线、可定位、内容代数一致。文件替换或重新绑定时建立新的 part 身份，不原地修改既有 part 的 file_id/bound_content_revision 来掩盖变化；旧断点可留作记录，但不再作为当前有效续播目标。单纯移动路径且文件身份未变时继续使用原坐标。

## 4 从点击到实际定位

```text
点击继续播放
  → 服务端读取最新有效断点，确定集 / 版本 / 文件段 / 毫秒
  → 幂等建立会话，固定起播目标
  → 客户端准备实际文件，暂不自动播放、不上报默认 0
  → 定位到目标，确认播放器实际位置
  → 开始实际播放，发送 start
  → 服务端确认 start 后建立 / 更新当前断点
  → 正常播放期间持续保存
```

Web 与 Android 共享该流程，通过各自播放器适配层报告“准备完成、定位完成、实际播放”。组件重组、页面重新渲染、时长回调和重连不能反复执行首次定位。用户退出时旧页面的迟到响应不得启动新播放器。

初次定位完成前，禁止将播放器默认 0 作为 progress/pause 发送；此时关闭页面只结束未开始的尝试，不写断点，也不增加播放次数。定位后如果浏览器仍要求用户手势，继续显示待播放状态，直到实际播放才发送 start。

start 携带实际坐标；服务端对照会话固定目标校验，首版定位验收容差目标为 2 秒。定位明显错误时返回 START_POSITION_MISMATCH，停止断点写入并由客户端重新定位；不会以“请求返回 200”代替真正定位成功。播放器不支持目标位置时保留原断点，让用户明确重试或改为从头播放。

## 5 接口与事务

### 查询播放计划

`POST /playback/plans` 只读查询，提交 mediaId 或作品组 ID、可选 editionId、intent（play/resume/restart）和设备能力。服务端返回 resolvedMediaId、episodeNumber、editionId、startMode、target（partId、positionMs）、播放能力和不可续播原因。URL 不含磁盘路径或长期账号凭据。

play 为普通入口：有有效断点则恢复，否则从头；resume 是用户明确点击继续，断点失效时返回可处理错误，不静默降级；restart 明确从头。作品组先解析实际集；组、剧、季都不能直接建播放会话。

### 建立会话

`POST /playback/sessions` 提交 resolvedMediaId、editionId、intent、设备 ID 与幂等键。服务端在事务内锁定个人作品状态，重查断点及文件有效性，分配新的 takeover_generation，保存最终 start_mode/start_part_id/start_position_ms。客户端必须以本次响应目标起播，不能继续使用可能过期的计划目标。

响应包含 sessionId、takeoverGeneration、固定 target 和受控媒体地址。重复同一请求返回同一会话和同一目标，不重复递增代数。创建阶段不修改播放位置、resume_edition_id 或播放次数；较早会话失去当前断点写入权，但已保存位置仍在。新尝试失败后再次点击会建立新尝试，不自动恢复旧会话的写入权。

### 接收事件

`POST /playback/sessions/{id}/events` 接收 eventId、seq、kind、partId、positionMs、takeoverGeneration；重试复用 eventId 和 seq。重复事件返回原处理结果，相同身份但不同内容报冲突，不执行两遍副作用。

服务端事务按统一顺序锁定 user_media_state、playback_sessions，再检查归属、文件内容代数、当前代数、序号与起播状态。start 必须先确认固定起播目标，首次成功时才设置 has_started、更新 resume_edition_id/last_played_at、写入 progress，并计一次真实播放。start 以前的 progress/pause/seek/ended 不更新进度或 last_seq，返回 SESSION_NOT_STARTED，避免乱序请求跳过启动确认。

已起播后接受递增 seq，允许跳号，主动后退同样有效；过期 seq 只确认不覆盖。较旧 generation 的补发可留诊断事件，applied_to_resume=false，不更新当前位置、最近时间或完成状态；返回 taken_over，旧客户端停止上报并提示会话已被接管。较新设备的真实进度永远不会被旧设备补发夺回。

每个有效事件同时更新事件行、会话 last_seq、版本进度及个人接续入口；只更新数据库成功后才返回持久化确认。位置按所属段已知时长校验范围，拒绝无效坐标，不把异常值归零。发生结束时，事务校验当前段是否为版本最后一段：中间段结束保留真实结束位置，后续计划将其解析为下一段 0；最后一段结束写 completed_at 并结束会话，保留结束坐标而非写回 0。同一会话切换物理文件段也要重新等待准备和定位，真实播放后才上报新段坐标，但不重复执行首次 start。

`POST /playback/sessions/{id}/close` 幂等结束播放尝试。已起播时可携带最终 pause 事件，在同一事务中先按事件协议处理，再关闭；未起播不携带默认 0，也不创建断点。已关闭/完成/过期的会话只确认重复请求，其余新动作须建立新会话；被接管会话的补发仅可作诊断。异常退出未成功 close 的会话按服务端过期规则收尾，不靠客户端一定发出离开请求。

首版有效恢复位置来自服务端已确认数据。客户端按顺序发送持久待发队列；开始新会话前尝试同步尚有效的旧事件，再请求服务端目标。旧会话已被接管时丢弃其覆盖资格，不能把本地旧坐标硬套到新会话。服务不可达时不新建离线播放会话。

## 6 上报、退出与跨端恢复

- 正常播放每 10 秒保存检查点；暂停、用户 seek 完成、切集、退后台和退出时立即提交真实位置。缓存、缓冲和尚未完成定位不生成默认零位置。
- 两端使用本地持久待发队列；只合并相邻 progress，保留 start、seek、pause、ended 等顺序边界。重试沿用稳定 ID，服务端确认后删除本地项。
- Web 不依赖关闭页面请求一定成功。异常退出只能保证已持久确认的最后检查点；在线正常状态验收恢复误差目标不超过一个 10 秒周期加定位容差。断网期间另一端只能读取服务端已确认位置，界面显示待同步状态。
- 新会话打开后旧设备补发不得覆盖；切换不同剪辑/版本使用各自断点。首版不按比例跨版本猜位置。
- 继续观看列表只包含未完成、坐标有效且位置大于 0 的真实进度；排序用有效进度的服务端时间，不能仅用迁入的 last_played_at。不可用记录在详情解释原因，不作为能成功续播的卡片。
- 作品组按有效子集状态聚合，不创建组断点。最近一集完成后可建议下一未完成集，目标集有有效断点则继续，否则从首段 0 开始；没有下一集则显示重新观看。

## 7 必须通过的真实播放器验收

| 场景 | 验收结果 |
| --- | --- |
| 首次起播 | 无历史进度，从首段 0 开始；打开后未起播不产生断点 |
| 同端重新打开 | 在 32:15 暂停并确认保存后，重新打开实际起播在该位置附近，目标容差 2 秒 |
| Web → Android / Android → Web | 两方向均读取服务端最新确认位置，实际定位后才上报，不能只检查接口中的 positionMs |
| 加载阶段退出 / seek 失败 | 原断点完整保留，不被默认 0 覆盖；给出重试或从头入口 |
| 拖到较早位置 | 40:00 回退到 12:00，后续从 12:00 继续；迟到的旧事件不跳回 40:00 |
| 95% 与自然结束 | 95% 未结束仍续播；真实播完移出续播，重新播放成功后才建立新一轮进度 |
| 第 2 集 / 第 2 文件段 | 选中正确集及文件；中间文件结束不把整个版本标完成 |
| 重试、乱序与重复点击 | 不多建同一会话、不重复计数、不跳过 start 确认，不回退到旧事件 |
| 旧设备离线补发 | 新设备接管后，旧事件不改变当前位置与完成状态 |
| 文件替换 / 媒体盘离线 | 不套用旧位置，不静默开始其他文件；原记录保留可解释原因 |
| 个人整理 | 喜欢、评分、手动已看、加入收藏夹不会清空或改变实际断点 |
| 初始化迁移 | 旧进度不进入新播放表，继续观看为空；喜欢、评分和收藏夹仍在 |

数据库约束检查只验证合法坐标、起播模式与外键等静态规则。启动顺序、接管事务、队列恢复和真实定位属于应用与播放器验收，当前尚未实现或实测。对应交付阶段为 M2（真实播放）和 M5（跨端及异常恢复）。

### 维护已发布版本的文件

- 重新检测核对媒体盘身份、登记路径、文件尺寸与修改时间，以及 FFprobe 读取结果。当前路径的内容有变化时，原版本绑定和续播进度继续对应原来的内容。
- 替换选择已核对的单文件草稿，支持比较和试播。整理完成后，归档原版本并发布新版本在同一事务完成。原版本若是默认版本，新版本继承默认标记。任一阶段失败时保留当前可用的播放版本，可从详情页重试。
- 新版本拥有独立的播放进度。旧版本已有的播放会话可继续使用原文件。原文件及进度保留，重新检测旧文件通过后可恢复源版本。
