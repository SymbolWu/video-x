# video-x 产品定位与体验规格

> 最新产品行为见[产品需求文档 1.0](product-requirements.md)。本文件继续说明视觉和导航；此前录入、文件移动和筛选的精简结论，以新 PRD 的能力承接及待评审建议为准。

> 2026-11-17：三端原型已与候选模型逐项核对；已修正的范围偏差和仍缺的页面见[原型与字段核对](prototype-schema-review.md)。旧原型能力清单不能替代逐列首版范围。


video-x 服务一个人的长期影视收藏：整理自己的文件和资料，在 Web 与 Android 上轻松找到想看的内容，并可靠地继续观看。体验定位为私人影院与个人资料库。管理工作台负责把资料整理好，观看端把作品、人物和观看选择呈现出来。

本规格初稿于 2026 年 11 月 12 日，2026 年 11 月 17 日同步单分类、人工发布和原生播放范围，配合[总方案](../../../home-media/docs/engineering/video-x-plan.md)使用。当前 HTML 原型 V0.3 已按下述定位收敛导航和页面层级；原型与正式工程的完成标准分别记录。

## 1 已确定的范围与设计基线

| 项目 | 约定 |
| --- | --- |
| 使用者 | 个人自用；一个账号和默认个人资料，不建设组织、团队或多租户体系 |
| 客户端 | Web 观看端、Web 管理端、Android；移动端优先观看和个人整理 |
| 部署 | 当前 Mac；用户登录后自动恢复服务；保留迁移到 Linux 的配置路径 |
| 网络 | 稳定出站用于资料抓取；首版按本机及家庭局域网使用，公网观看以后按需增加 |
| 内容范围 | 自己拥有的媒体和对应资料；演员页、系列页默认展示已入库的作品 |
| 视觉 | 沿用参考主题的深灰、粉红与蓝色，结合海报、人物和留白形成影院体验 |
| 文件 | 下载目录多选、草稿设置整理目标、手动移动发布；已整理视频可原位建库。见[文件整理](storage-intake.md) |
| 分类 | 作品、演员各属一个分类；可设置喜剧片、动作片等分类，在观看端直接筛选 |
| 入库 | 扫描、探测和抓取只产生待核对资料；所有入库均由人工确认、手动发布 |
| 播放 | MP4、MKV 为首批文件识别与验收范围；按真实容器、编码和客户端能力原生播放，转码及服务端重封装后置 |

首版包括演员、系列、收藏夹和分类的完整浏览与维护，它们属于资料库的基本组织方式。增加来源、硬件转码、离线下载、多人共享、智能片单和公网观看列入后续范围。

## 2 体验原则如何决定功能位置

| 原则 | 在产品里的表现 | 评审时观察什么 |
| --- | --- | --- |
| 内容先于字段 | 卡片以海报、片名、必要状态为主；资料页先给观看选择 | 用户能否迅速选片，是否被编码、路径和来源信息打断 |
| 从当前兴趣继续探索 | 影片 → 演员 → 参演影片；影片 → 系列 → 下一部 | 关系入口是否自然出现在用户产生兴趣的位置 |
| 常用操作就近完成 | 喜欢、加入收藏夹、续播在作品和播放器附近 | 是否为一次收藏跳进管理端，返回后是否丢失位置 |
| 维护有明确场所 | 编辑资料、合并、批量归类、来源差异在管理端 | 管理功能是否挤占观看页的主按钮和首屏 |
| 状态可理解 | 区分没有收藏、未入库、硬盘离线、抓取失败和播放不兼容 | 空白或失败页面是否能告诉用户下一步做什么 |
| 保留用户上下文 | 返回时保留筛选、滚动、搜索和所选版本 | 从演员作品返回后是否需要重新寻找人物 |

新增一个业务对象时，先回答它帮助用户完成哪项选择、从哪里进入、主要动作是什么、离开后回到哪里，再决定页面和组件。数据库有一张表，并不直接决定观看端增加一个一级菜单。

## 3 信息架构与跨端分工

### 3.1 观看 Web

顶级导航建议收敛为「发现、片库、收藏」，全局搜索位于顶栏，观看历史和设置位于个人入口。顶级导航回答“现在想做什么”；片库内部回答“按什么找”。

片库包含「影片、演员、系列」三个视图，共享当前分类范围。分类使用“全部、喜剧片、动作片……”这样的单选筛选条，分类多时使用选择面板；有层级时辅以面包屑。年份、标签、已看状态等使用筛选面板。分类也有可分享和返回的独立落地页，但不占用一级导航。

片库顶部将分类与显示、排序、筛选按用途分组，控件高度、文字基线与图标尺度一致。切换到演员或系列时使用对应类型的排序和筛选，不能保留无效的影片控件。窄屏按可读和可操作的顺序重排，不把文字挤成竖排。

片库 Header 中，影片、演员、系列采用线型页签；分类采用单选胶囊，选中样式与页签区分。排序、筛选与视图切换作为次级工具统一排布，结果数量只保留一处。标题区不使用包住全部控件的大面积玻璃底板，也不整块吸顶遮挡海报；玻璃效果保留在导航与必要浮层。手机分类横向滚动，重新渲染后保持选中项可见。组件层级参考 [Carbon 页签](https://www.carbondesignsystem.com/building-blocks/core/components/tabs/guidelines)、[视图切换](https://www.carbondesignsystem.com/building-blocks/core/components/content-switcher/guidelines)与 [Material 筛选胶囊](https://developer.android.com/develop/ui/compose/components/chip)。

这个层级让三种视图共享检索与返回上下文，也为内容留下更多空间。代价是主动按演员找片可能多一次切换，因此演员视图应有独立 URL、记忆当前片库视图，并能从喜欢的人物直接进入。下一轮用“经常按演员选片”的任务评审入口是否足够明显，再固定导航。

| 页面 | 主要任务 | 主要入口 | 主操作 |
| --- | --- | --- | --- |
| 发现 | 接上上次观看，或找一部想看的作品 | 默认首页 | 继续观看 / 播放 |
| 片库 | 按作品、人物或系列寻找内容 | 一级导航 | 筛选并进入资料详情 |
| 收藏 | 查看喜欢的影片、喜欢的演员和自建收藏夹 | 一级导航 | 进入收藏夹 / 新建收藏夹 |
| 搜索结果 | 找到名称、详细名称或编号对应的资料 | 顶栏搜索 | 进入结果；按影片/演员/系列切换 |
| 历史 | 回顾观看活动并接续 | 个人入口、首页“查看全部” | 继续观看 / 管理历史 |

首页先显示有实际断点的“继续观看”，再显示最近加入、个人收藏和少量探索推荐。可放“最近收藏的演员”或“沿着一个系列看下去”，由现有资料生成；空库时显示建库引导，演员资料不足时不展示空书架。

### 3.2 Android

底栏采用「发现、片库、收藏、我的」。片库的影片/演员/系列切换与 Web 保持同一语义；搜索位于发现和片库顶部；分类范围使用底部选择面板。演员、系列与影片详情使用正常的返回栈，不增加底栏项目。

个人收藏夹可在手机上完整整理。合并人物、批量归类、来源设置和文件管理先在 Web 管理端完成。移动端资料问题可以显示“资料有误，前往管理端维护”的入口说明，首版不嵌入桌面表单。

### 3.3 Web 管理端

按工作分成三组：入库工作台；资料维护（作品、演员、系列、分类、收藏夹）；运行管理（来源、任务、系统）。有待处理任务时显示数量，任务完成后提供“在观看端查看”。

管理页可以使用表格、多选和密集表单，但继续使用统一的颜色、字体和状态语义。演员编辑从演员页或影片关联面板打开，返回后保留原来的筛选与选中项。管理员仍是同一个个人账号，通过服务端会话和操作权限保护写接口。

## 4 演员如何融入观影体验

### 4.1 发现与进入

主路径为「作品详情的演员区 → 演员详情 → 另一部参演作品」。片库的演员视图服务主动按人找片；搜索同时匹配常用名与详细名称。首页的演员推荐是补充入口，不能成为访问演员的唯一方式。

演员区展示头像、姓名和职责，点击整个人物卡片进入详情。没有头像时使用统一的文字占位，避免破图。演员很多时显示一排并提供“查看全部”，不把影片的播放选择挤出首屏。

演员目录使用比影片海报更小的人物卡片，姓名与片库作品数紧邻头像。少量人物不自动放大到占满整行；有图、缺图和长姓名保持同档尺寸。

作品和人物详情默认用于浏览，用户点击播放或继续观看才建立播放会话。现有 Android 进入作品详情即自动播放的行为在新产品中调整，避免查看演员或版本时意外起播；已经打开的播放器则按生命周期和用户暂停意图恢复。

### 4.2 演员详情页面蓝图

| 页面区域 | 内容与布局 | 交互与限制 |
| --- | --- | --- |
| 返回区域 | 返回来源页及分类上下文 | 回到原影片或片库位置，而非固定返回首页 |
| 人物概览 | 头像、姓名、详细名称、已入库作品数量 | 首版不展示人物简介、生日、角色名；性别与分类留给资料面板，人物不设无依据的本地编码 |
| 个人动作 | 收藏演员；必要的更多操作 | 收藏后进入“收藏 → 演员”；不替代影片的喜欢状态 |
| 参演影片 | 海报网格，显示“片库内 N 部” | 默认按发行时间倒序，可切最近加入；支持未看、已看等筛选 |
| 资料尾部 | 资料来源和更新时间的简要说明 | 需要维护时进入管理端对应演员；来源授权信息不出现在观看端 |

演员页的主要价值是找到作品，因此不把完整履历、来源字段或维护按钮做成大面积首屏。默认不自动播放，也不凭演员作品数量杜撰“人气”或评分。

演员作品页有独立 URL、人物概览和“参演作品”标题，可以复用影片网格组件，但不能以全片库的临时筛选结果替代。人物是固定范围，清空页内搜索或筛选仍只展示该人物的馆藏作品。从此页进入影片，再返回时恢复人物页的筛选、排序、滚动和触发焦点；再次返回恢复原演员目录或来源影片。

演员与系列作品页的工具区沿用片库的轻量层级：作品标题旁显示当前结果数，筛选后显示结果数与该实体总数；不再另占一行重复计数或显示“片库内作品”图标标签。标题与排序、筛选、视图切换统一排布，分类在下方使用胶囊态，仅保留底部分隔线，不用整块底板或大面积吸顶。窄屏按标题、分类、工具分行，触控命中区至少 44 CSS px，长排序名称缩略且可在菜单完整读取。

计数按不同的作品去重，多版本和同一作品的多个演员角色不重复计数。没有关联影片时保留人物概览并解释“暂未关联片库作品”；可以返回演员列表，管理端提供整理关联入口。

### 4.3 演员维护与反馈

管理端支持新增、维护常用名与详细名称、头像、分类、人工字段锁定、参演关系、合并和归档。创建时检查来源 ID 和近似姓名，提示候选，由用户决定是否复用人物；同名不自动合并。

从影片维护演员时，先搜索已有演员，再创建缺失资料。新建后自动回到原关联面板并选中人物。合并先展示双方资料、关联影片和字段冲突；确认后保留目标人物，迁移关系、来源身份及个人收藏，旧链接转到目标人物。

观看端在保存成功后刷新受影响的人物、影片和搜索缓存；加载失败不显示“暂无作品”。具体事务规则见[数据规格](data-model.md)。

## 5 系列 收藏夹与分类的体验定位

### 5.1 系列帮助连续探索

系列表达作品之间已有的创作或发行关系。入口位于影片详情、片库的系列视图及首页探索书架。详情展示封面、简介、片库内数量和有序作品，作品卡片仍可正常打开详情。

系列目录封面以成员海报组合呈现影片集，标题和馆藏部数直接可读。只有一部馆藏时保留系列的视觉身份，不重复同一张海报假装有多部；多部时展示不同成员的海报，缺图使用稳定回退。馆藏数量不表示全系列已收齐。

组合封面采用同方向、等步幅错位叠放：主封面在前，后方露出不同成员的封面边缘，目录与系列详情使用相同规则。避免随机高低散排，单部仍只呈现一张海报。长页评审使用独立的多作品样本系列，成员、计数和返回位置一致；不向真实媒体库写入样本。

本轮 OpenDesign 观看端设计资产归档在 [design/2026-11-opendesign](../../design/2026-11-opendesign/README.md)，包含当前完整原型、安装与协作方式、素材来源、设计演进及验收证据。原型使用本地样本，正式应用的产品规则仍以本文件及对应专题为准。

系列作品页有独立 URL、系列概览与成员列表，不以全片库的临时筛选结果替代。默认按保存顺序展示，切换浏览排序不修改成员保存顺序；清空筛选保留系列范围。进入成员影片后逐层返回，恢复各层的浏览上下文。

主动作根据状态显示“开始观看”或“继续该系列”。首版“继续”定位最近播放的系列内作品及其断点；无断点时定位第一部未看作品；全部已看时回到第一部并显示状态。它不会默认连续自动播放下一部，用户在片尾选择是否继续。

管理端编辑系列资料、成员和顺序。排序有明确的序号与上下移动，拖拽只是桌面增强；小屏和键盘仍能操作。系列不是电视剧的剧/季/集容器，个人主题片单使用收藏夹。

### 5.2 收藏夹服务个人整理

收藏页分为「喜欢的影片、喜欢的演员、收藏夹」。喜欢是快速标记；收藏夹支持一部作品进入多个分组，属于当前个人资料。二者互不隐式联动。

作品详情和卡片更多菜单都可“加入收藏夹”，打开多选面板并保留现有选择；面板可立即新建收藏夹，新建后仍回到当前作品。收藏夹详情展示说明、封面、数量和有序作品，整理模式才出现批量选择、移出和排序控制。

默认以观看模式打开收藏夹，避免每次进入都看到删除按钮和排序工具。删除先说明“收藏夹及其收录关系将归档，影片、喜欢状态和观看记录保留”。空收藏夹显示添加入口。手动指定的封面与自动封面策略在管理及移动端一致。

### 5.3 分类定义浏览范围

用户已确认作品、演员各属一个分类；系列沿用单主分类方案。分类支持父子层级，可以直接命名为“喜剧片、动作片”等，首版由现有 categories 表承接，不要求先实现独立 genre 域。标签可补充多个特征，物理媒体根单独管理。未指定分类时归系统“未分类”，不建立多分类关联。

观看端以“全部”为默认，选中一个分类后筛选列表，不修改作品归属。父分类默认包含后代；切换分类回到第一页，分类写入路由，详情返回保留分类、筛选和滚动。Web 使用筛选条，Android 使用同义的筛选条或选择面板，不把分类维护表格放进观看流程。

片库顶部显示当前范围，分类页可在“影片、演员、系列”间切换。父分类默认包含后代，计数和列表使用同一范围。进入演员后默认展示其全部已入库作品，同时提供当前分类筛选，避免把人物作品误当作仅属于一个分区。

分类保留“显示 / 隐藏”开关，用于收起暂时没有影片的入口，不自动根据影片数量切换。隐藏只从范围选择器和分类导航移除该分支；影片仍可出现在全部片库、搜索、演员和系列中，管理端始终可查看并重新显示。

从显示改为隐藏时，检查该分类及子分类的影片数。没有影片则直接保存；有影片则提示“该分类及子分类下有 N 部影片（本级 D 部、子分类 S 部），隐藏后仍能从全部片库和搜索找到”，提供取消与继续隐藏。提示允许确认后继续，不禁止隐藏有影片的分类。列表快捷操作与编辑表单保存共用规则；取消表单提示返回编辑并保留输入，隐藏本身不改名、不迁移影片或修改收藏/断点。

数量与观看端分类影片列表保持同一口径：已发布、未归档作品按作品身份去重，版本与文件不重复计数，离线作品仍计入；父分类包含全部后代，已隐藏子分类的作品也计入。预览至保存间数量/范围变化则更新提示。后续有新影片归入时保留原显示开关，由用户手动调整。

管理端提供树形维护、顺序、可见性和影响预览。删除分类必须指定分支外的迁移目标，说明迁移的作品、人物、系列及子分类去向；保留系统“未分类”。

### 5.4 入库由人工决定

后台可自动扫描、探测和抓取候选，结果只进入工作台草稿。ready 表示已经具备发布条件，仍需人工核对并点击“发布”；高匹配度、任务完成、定时扫描或重启恢复都不触发自动入库。允许核对多项后主动批量发布；发布期间草稿或候选变化则重新核对。

已入库资料刷新同样先展示差异，人工接受后才写正式资料，人工锁定继续生效。观看端只展示已经发布的作品及其正式关系，不将抓取到的新人物或系列提前当作已入库资料展示。

## 6 视觉与交互的一致性

| 维度 | 观看端 | 管理端与移动端的对应规则 |
| --- | --- | --- |
| 颜色 | 背景 #0f1013；面板 #17181d；卡片 #1c1d23 | 三端使用同一语义令牌；状态不能只靠颜色识别 |
| 强调 | 以 `packages/design-tokens/tokens.css` 的 `--accent` 为准（当前为 #ff6f91），用于选中、喜欢、品牌和主动作；透明度与悬浮状态由此派生 | 三端沿用令牌来源；同一操作采用相同语义，一个局部操作区保留清楚的主动作 |
| 内容比例 | 作品以海报为主，人物以头像为主；系列和收藏夹用主封面或封面组合 | 保持媒体类型可识别，缺失资源有稳定占位，避免布局跳动 |
| 页面节奏 | 概览适量，内容列表及时出现，长简介折叠 | 管理端密度提高但分组清楚；Android 首屏保留主动作和部分内容 |
| 卡片动作 | 点击进入详情；更多菜单放次要动作 | 移动端有显式操作入口，不能依赖鼠标悬停 |
| 整理模式 | 收藏夹等页面显式进入整理，完成后回到观看模式 | 手机支持上下移动；排序后即时反馈和失败恢复 |
| 表单 | 观看端只保留个人整理所需的短表单 | 长资料表单在管理端；关联选择器支持搜索、已选状态与就地新建 |
| 反馈 | 保存中、保存成功、冲突和失败可区分 | 失败保留输入；再次提交有幂等保护；不能先显示成功再静默失败 |
| 可访问性 | 键盘焦点、可读对比、图片替代文字、减少动画偏好 | 手机触控区域建议至少 44 CSS px；Android 使用至少 48 dp，实施时检查组件实际命中区域 |

影片详情中并排的播放或继续播放按钮与版本选择按钮，实际外框高度及上下边线一致。长版本名称和规格在按钮内缩短或省略，完整内容在版本下拉菜单中可读，不能由换行撑高单个按钮。

版本选择使用锚定在触发按钮旁的下拉菜单，展示名称、可得规格、当前选中和默认版本。点选后立即切换并收起，不增加确认弹窗，不因选择版本自动播放。菜单支持键盘选择、Esc 关闭与焦点返回、点外部关闭；手机同样就地展开，并按视口空间调整位置和滚动范围。

各页的导航、控制区和浮层适量使用深色毛玻璃，保留清楚的文字对比与边界。海报、人像和正文内容保持清晰；降低透明度或无法模糊时使用实色表面回退，不影响选中、焦点和操作反馈。

高保真 HTML 原型应提供真实可操作的状态过渡：影片、演员、系列页签共用可移动的底部指示线，结果区域短暂交叉淡入淡出；连续切换时以最后选择为准并清理旧图层。排序使用锚定触发按钮的菜单，显示当前选项、展开状态并支持键盘选择。筛选打开、取消与应用都有短暂过渡，取消不改变条件，应用后保留可辨的已启用提示。开启系统减少动画偏好时，立即完成状态变化。

海报上的喜欢按钮通过透明表面、背景模糊、细边框与内高光表达玻璃材质，保持 44 CSS px 命中区。点按后原位更新爱心并给出短暂反馈；只看喜欢时取消喜欢，应同步移出结果。当前 Logo 设计探索采用 V/X 与播放负形的矢量标记，颜色跟随 `--accent`，不更改产品名称。

页面、弹窗和下拉菜单的原生滚动条采用细圆角滑块与透明轨道，悬停提亮、拖动时使用柔和强调色。桌面预留稳定滚动槽，避免切换内容长度时左右跳动；保留滚轮、拖动、键盘与手机原生触控滚动。

Android 触控区域与组件默认行为按 [Compose 可访问性文档](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)验证；Web 的 44 CSS px 为本项目的触控设计目标。

## 8 V0.3 原型如何评审

V0.3 已调整整体结构：Web 一级导航收敛；影片、演员和系列进入统一片库；分类变为范围入口；收藏页增加喜欢的演员；收藏夹默认展示作品，整理控件进入整理模式。演员合并增加影响预览和字段选择，归档与恢复覆盖本地资料。具体已验证流程和边界见[原型说明](../../../home-media/prototypes/video-x/README.md)。

用三条连续任务评审，而非逐页看截图：

1. 从首页续播作品，暂停后看演员，找到另一部未看作品，加入新收藏夹，再回到原片继续。
2. 在片库切到演员视图，用详细名称找到人物，切换分类与已看筛选，进入系列并找到下一部。
3. 导入时发现重复演员，进入管理端预览并合并，回到观看端确认作品数量、头像、详细名称和个人收藏一致。

评审应覆盖有资料、缺图片、零作品、硬盘离线、请求失败和窄屏状态。路线、主按钮、返回位置和失败恢复成立后，再固定组件尺寸和动画细节。完整验收矩阵见[实施与验收](delivery.md)。

### 观看端设计回归补充（2026-11-27）

以下用例承接本轮视觉评审，原型通过不代替正式应用验收：

| 场景 | 操作与预期 |
| --- | --- |
| 顶部控制区 | 在影片、演员、系列间切换，核对控件用途、对齐、激活与键盘焦点；页签与分类选中态可区分，结果数量随条件更新。窄屏文字不竖排，分类横向滚动后选中项仍可见；筛选取消不改变结果，滚动后的 Header 不遮住大面积内容。 |
| 演员目录 | 同时放入有图、缺图、长姓名与少量人物；卡片保持较小尺寸，姓名和作品数可读，不随样本数量放大。 |
| 系列封面 | 同时展示馆藏一部、两部、三部的系列；组合可辨，单部不伪造多部，封面与部数对应实际成员。 |
| 系列长页与叠放 | 使用至少 25 部不同作品的样本系列滚动至中段和底部；进入影片后返回恢复原卡片焦点与滚动位置。封面叠层均来自该系列不同成员，前后层级和偏移有序；目录、详情、手机与减少动画偏好下均正常。 |
| 独立下钻与范围 | 演员目录或系列目录 → 独立作品页 → 影片 → 逐层返回；逐层恢复状态。作品页搜索至零结果后清除条件，仍只显示当前人物或系列的作品。另验影片 → 人物或系列 → 另一影片的返回路径。 |
| 作品区工具条 | 演员和系列详情均核对标题旁数量与实际结果一致，筛选后总数仍为当前实体范围；没有重复计数行或整块吸顶底板。桌面和 390/320px 下分类、排序、筛选与视图切换可操作，长排序名称不挤出视口；进入影片再返回，条件和触发焦点恢复。 |
| 播放与版本对齐 | 在桌面和窄屏分别放入普通播放、继续播放、长版本名称与规格；测量两个按钮实际高度相同，完整规格可在下拉菜单读取。 |
| 版本下拉交互 | 鼠标、触控及键盘展开与选择，点选后立即更新并收起；Esc 返回触发按钮，点外部关闭，Tab 正常离开。切换不开始播放、不修改个人状态或断点；窄屏与滚动后菜单不裁切、不越出视口。 |
| 毛玻璃可读性 | 在片库、演员和系列目录及各详情页检查导航、控制区和浮层的材质层次；图片与正文保持清晰，滚动及打开菜单时文字仍可读。减少透明度与不支持模糊时，实色回退和所有操作保持可用。 |
| 品牌与强调色 | 对照令牌文件核对 `--accent` 的计算值，Logo、页签指示线、喜欢与菜单选中态均使用该值或其透明派生；矢量标记在桌面和手机均正常显示。 |
| 动效与排序筛选 | 实测指示线移动与结果交叉淡入淡出，快速切换后没有残留图层；鼠标、触控和键盘均可排序。筛选取消恢复焦点且不改结果，应用后结果与启用提示一致；减少动画时所有操作立即完成。 |
| 喜欢按钮玻璃与反馈 | 在明、暗海报上核对背景模糊与边缘高光；点按原位改变爱心，普通列表不整体重建。只看喜欢时取消后移出结果；减少透明度时保留可读实色回退。 |
| 滚动条 | 在长片库与短目录间切换，核对页面无横向跳动；滚轮、拖动和键盘可滚至底部，菜单内部滚动可用。细滑块与透明轨道保持可辨，手机无横向溢出，分类横向滚动仍可用。 |

## 首版范围确认（2026-11-16）

个人自用，单账号默认资料；不设计多账号公网入口。上下部/Part1/Part2 作为作品组中的有序分集，组详情提供选集，每集单独播放和续播，不强制显示“季”。人物生日、简介、角色名等后置；没有数据时不留空表单占位。旧任务不迁入任务中心。

## 观看进度重建设计（2026-11-16）

旧观看进度与断点不迁，初始化无继续观看卡片。新续播必须实际定位到对应集/版本/文件段的毫秒位置后才开始播放与保存；加载失败不把断点写回 0，95% 未结束仍可继续，播放完成与手动已看分别处理。完整规则和验收见[观看进度与继续播放](playback.md)。文件大小重读实际文件，历史喜欢状态保留且时间可空。
